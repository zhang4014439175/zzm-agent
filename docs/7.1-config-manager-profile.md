# 7.1 ConfigManager、Profile 与配置作用域

## 一句话说明

7.1 引入统一配置管理层，让 zzm-agent 能按全局、项目、本地和托管作用域加载配置，并能说明每个生效配置值来自哪里、是否被管理员锁定。

## 解决的问题

之前 CLI 直接读取一个 `config.yaml`，虽然简单，但会带来几个问题：

- 用户不知道当前模型、插件目录、stream 开关到底来自哪个配置文件；
- 项目配置和本地私有配置没有正式作用域，后续容易把 API key、个人偏好或本地路径误提交到仓库；
- 没有 profile，用户切换 fast / review / safe 等配置组合时只能手动改 YAML；
- 没有托管配置或锁定项，团队/企业策略无法声明“这些安全配置不能被项目或本地覆盖”；
- 后续 `/config`、桌面设置页、CI 非交互入口都缺少统一配置来源审计。

7.1 的目标是先建立配置加载和审计基础，后续 P2 的 CLI 命令、P3 沙箱、P4 MCP/Plugin 和 P10 托管治理都可以复用。

## 具体例子

假设有三个配置文件：

全局配置：

```yaml
model:
  model_name: global-model
agent:
  stream: true
memory:
  max_context_tokens: 16000
```

项目配置：

```yaml
model:
  model_name: project-model
memory:
  path: .zzm_agent/memory.json
```

本地配置：

```yaml
agent:
  stream: false
```

加载后生效结果是：

```text
model.model_name = project-model      来自 project
agent.stream = false                  来自 local
memory.max_context_tokens = 16000     来自 global
memory.path = .zzm_agent/memory.json  来自 project
```

用户在 CLI 输入：

```text
/config
```

会看到当前关键配置值、来源 scope、配置文件路径和 locked 状态。这样后续排查“为什么当前模型不是我想的那个”时，不需要猜。

## 使用场景

- 用户启动 CLI 时，`load_config()` 通过 ConfigManager 加载配置；
- 用户使用 `ZZM_AGENT_PROFILE=fast` 切换 profile；
- 项目仓库提交 `config.yaml`，团队共享模型、插件和默认行为；
- 用户在 `.zzm_agent/config.local.yaml` 放本地偏好，例如关闭 stream 或修改 memory 路径；
- 管理员或托管环境提供 managed config，锁定安全项，例如模型网关、权限 profile、沙箱 profile；
- 用户运行 `/config` 查看当前生效配置和来源。

## 执行链路

```text
CLI main()
→ load_config()
→ ConfigManager.resolve_default_sources()
→ ConfigManager.load()
→ 按 global / project / local / managed 合并配置
→ 展开 ${ENV:-default}
→ 应用 profiles.<name>
→ 记录 _config_sources / _config_origin / _config_locked
→ build_runtime()
→ /config 可展示当前生效配置
```

默认配置来源顺序：

```text
~/.zzm_agent/config.yaml             global
<repo>/config.yaml                   project
<cwd>/config.yaml                    project
<cwd>/.zzm_agent/config.local.yaml   local
```

如果用户传入 `--config` 或设置 `ZZM_AGENT_CONFIG`，会优先使用指定文件，保持旧行为兼容。

## 关键事件或数据结构

### `ConfigScope`

支持：

- `global`
- `project`
- `local`
- `managed`

### `ConfigSource`

记录一个配置输入：

```python
ConfigSource(
    path=Path("config.yaml"),
    scope=ConfigScope.PROJECT,
    name="workspace",
)
```

### `_config_sources`

写入最终 config，供 CLI 或桌面端展示：

```json
[
  {
    "path": "E:/repo/config.yaml",
    "scope": "project",
    "name": "workspace"
  }
]
```

### `_config_origin`

记录每个生效叶子配置值来源：

```json
{
  "model.model_name": {
    "key": "model.model_name",
    "scope": "project",
    "path": "E:/repo/config.yaml",
    "locked": false
  }
}
```

### `_config_locked`

记录不可被后续配置覆盖的键：

```json
["model.base_url", "agent.permission_profile"]
```

托管配置例子：

```yaml
managed:
  locked_keys:
    - model.base_url
model:
  base_url: https://gateway.example/v1
```

后续 local/project 再写 `model.base_url` 也不会覆盖这个值。

## 边界与非目标

7.1 不解决：

- 不提供完整 `/config set`、`/config edit`、`/config profile` 命令；
- 不实现权限 profile 或沙箱 profile 的具体执行策略；
- 不迁移所有命令到配置服务层；
- 不实现桌面设置页；
- 不实现企业远程托管配置下发，只先支持 managed scope 和锁定语义。

这些能力会在 7.3、P3、P9 和 P10 继续扩展。
