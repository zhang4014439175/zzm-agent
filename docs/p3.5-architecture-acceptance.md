# P3.5 架构收敛阶段验收

## 1. 一句话说明

确认 8.7 到 8.11 的 Runtime、Workspace、CLI 和事件边界已经形成可继续扩展的稳定基线。

## 2. 为什么需要它

单个重构任务通过并不等于整个阶段已经收口。P3.5 同时调整了 AgentLoop、运行状态、Workspace 副作用、RuntimeEvent、CLI 目录和安全出口，如果缺少阶段验收，后续 MCP、Skills 和异步任务可能重新依赖旧入口或绕过统一边界。

## 3. 一个实际使用例子

用户在 CLI 中要求修改文件并暂存：

    zzm-agent exec "修改 README.md，然后暂存这个文件"

CLI 通过 QueryEngine 提交任务，文件修改和 Git 索引操作分别进入 WorkspaceFilesystem 与 WorkspaceGit，产生 EffectRecord；运行事实写入 RuntimeEvent，旧 CLI 和事件导入路径仍然可用。

## 4. 功能的大致流程

1. CLI bootstrap 装配 AgentLoop 和 QueryEngine。
2. repl 或 execution 只通过 QueryEngine 发起请求。
3. AgentLoop 将工具执行委托给协调器和工具运行时。
4. 文件、Shell 和 Git 副作用进入 WorkspaceRuntime 适配器。
5. RuntimeEvent 与 ExecutionJournal 记录统一运行事实。
6. 兼容门面维持旧导入路径，Replay 验证既有行为。

## 5. 开发前和开发后的区别

开发前核心循环、状态、CLI 和副作用职责互相交叉，事件协议也缺少统一版本和顺序。开发后各层拥有明确入口：QueryEngine 协调任务，WorkspaceRuntime 管理副作用，RuntimeEvent 记录事实，CLI 只负责装配、输入和展示。

## 6. 现在已经支持的能力

- AgentLoop 职责已拆分并保留兼容入口。
- Application、Conversation、Turn、Loop、Permission 和 Cancellation 状态已分层。
- 文件、Shell 和 Git 副作用具备统一 EffectRecord 边界。
- RuntimeEvent 与 ExecutionJournal 支持版本、顺序、筛选和 Replay。
- CLI Runtime、Slash Command 和 UI Renderer 已目录化。
- 普通事件和工具日志具备 Secret Redaction。
- 外部工具内容具有来源和信任标签。

## 7. 当前限制（还做不到什么）

SQLite Journal、Hunk Tracker、Codebase Graph、快速快照和 File Watcher 仍是 P3.5 可选扩展，不属于核心阶段验收门槛。异步运行、MCP 和 Skills 将在后续阶段开发。

## 8. 给开发者看的实现位置

- zzm_agent/core/：AgentLoop、QueryEngine 与分层状态。
- zzm_agent/workspace/：统一副作用和 EffectRecord。
- zzm_agent/runtime/：RuntimeEvent 与 ExecutionJournal。
- zzm_agent/cli_support/：bootstrap、execution、repl、commands 和 ui。
- tests/test_p35_architecture_acceptance.py：静态架构边界。
- tests/test_agent_replay.py：既有行为与 Replay。
- tests/test_workspace_runtime.py：副作用与撤销。

## 9. 测试如何证明它有效

阶段定向验收同时检查 CLI 不直接依赖 AgentLoop、三类副作用入口使用 WorkspaceRuntime 适配器、旧事件导入保持同一类型身份，并复用 Replay 和 WorkspaceRuntime 测试证明重构没有改变关键行为及撤销语义。
