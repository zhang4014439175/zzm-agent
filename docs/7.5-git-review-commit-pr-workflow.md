# 7.5 Git / Review / Commit / PR 工作流

## 一句话说明

这项能力把日常 Git 交付动作收进一个可审查的 CLI 工作流：用户能查看和审查改动、经确认暂存或取消暂存、生成有测试依据的提交与 PR 文案，并把 CI 日志保存为 Artifact 后获得可执行的失败分析。

## 解决的问题

过去 `/review` 只覆盖只读 diff 审查，其余 Git 动作只能由用户临时拼 Shell 命令。这样容易把工作区改动、暂存区和提交范围混在一起，也无法保证生成的 commit/PR 描述引用真实测试结果。CI 日志通常只是一次性粘贴进 prompt，既没有稳定的 Artifact 引用，也很难在后续 Turn 中追踪。

本阶段建立的边界是：状态、审查和文案生成保持只读；唯一直接修改 Git 的操作是 stage/unstage，它们必须走运行时确认回调，并记录一个可立即反向执行的 index 操作。直接 commit、创建或切换分支、push、创建远程 PR 暂不执行，因为这些动作不能都用同一种可靠方式自动回滚。

## 具体例子

用户修改 `parser.py` 并运行测试后，可执行：

1. `/git status` 查看当前分支、短状态，以及 staged/unstaged diff 的规模；
2. `/review` 对当前未提交改动做只读审查；
3. `/stage parser.py tests/test_parser.py`，CLI 通过与工具执行相同的 `confirm_tool` 权限入口询问确认；
4. 若暂存范围不对，执行 `/git undo`，系统运行对应的 `git restore --staged -- ...` 恢复 index；
5. `/commit-message` 让 QueryEngine 检查 diff 和已有测试证据并生成提交说明；
6. `/pr` 生成包含 Summary、Tests、Risks 的 PR 草稿，而不发布远程 PR；
7. CI 失败后执行 `/ci build.log`，完整日志保存为 `ci-log` Artifact，分析回答引用 Artifact ID、首个可操作根因、相关代码和验证命令。

## 使用场景

- 日常开发中需要确认“哪些内容将进入下一次提交”；
- 提交前希望对工作树或暂存区做只读 review；
- 希望 commit message、分支名和 PR 描述与实际 diff、测试证据一致；
- CI 日志很长，需要保存完整证据，同时让模型给出紧凑的根因分析；
- 自动化或安全环境中不允许 CLI 静默修改 Git index。

## 执行链路

```text
REPL slash command
  -> handle_slash()
     -> /git: GitWorkflow -> git subprocess -> snapshot/index result
        -> 写操作: AgentLoop.confirm_tool -> stage/unstage -> inverse undo record
     -> /review、/commit-message、/branch、/pr
        -> QueryEngine.submit_message() -> read-only agent analysis -> terminal renderer
     -> /ci <log>
        -> read log -> ArtifactStore.save_text(kind="ci-log")
        -> QueryEngine.submit_message() -> root cause + fix + verification
```

## 关键事件或数据结构

- `GitSnapshot`：同时保存 branch、porcelain status、staged diff 和 unstaged diff，避免把不同改动范围混为一谈。
- `GitWorkflow._undo`：只保存最近一次 index 写操作的逆命令；成功回滚后清空，防止重复回滚。
- `ArtifactRecord(kind="ci-log")`：记录 CI 日志的 ID、摘要、大小和内容位置。分析 prompt 引用 Artifact ID，并把日志明确标记为不可信数据。
- QueryEngine 的流事件沿用 7.3A 的 renderer，不新增一套 Git 专属自然语言流协议。

## 代码定位

- `zzm_agent/cli_support/git_workflow.py`
  - `GitWorkflow.snapshot()`：读取分支、状态和两类 diff；
  - `stage()` / `unstage()`：校验路径、要求确认、修改 index 并记录逆操作；
  - `undo_last_index_change()`：确认后执行逆操作；
  - `_run()`：使用参数数组调用 Git，不经 Shell 拼接；
- `zzm_agent/cli_support/commands.py`
  - `_handle_git()`：实现 `/git status|stage|unstage|undo` 以及 `/stage`、`/unstage`；
  - `_handle_git_draft()`：生成 commit message、branch name 和 PR 描述草稿；
  - `_handle_ci_analysis()`：读取日志、创建 Artifact、提交只读分析；
  - `_git_confirm()`：复用 AgentLoop 的 `confirm_tool` 权限入口；
- `zzm_agent/cli_support/rendering.py`：补充相关 slash completion 描述。

## 边界与非目标

- `/commit-message` 只生成文案，不执行 `git commit`；
- `/branch` 只建议分支名，不创建、删除或切换分支；
- `/pr` 只生成描述，不访问远程托管平台；
- stage/unstage 的自动回滚记录仅保留最近一次操作，进程重启后不恢复；持久化 ChangeSet 属于 8.4；
- `/ci` 当前接收本地 UTF-8 文本日志，完整日志保存至 Artifact，但 prompt 最多内联前 20000 字符；
- release notes、远程 PR 发布和在线 CI 拉取需要后续 GitHub/CI 集成，不在本阶段伪装为已完成能力。

## 测试与验证

- `tests/test_git_workflow.py` 覆盖 staged/unstaged diff 分离、拒绝未确认写操作、stage/unstage 双向回滚和 Git option 注入防护；
- `tests/test_cli.py` 覆盖 commit/branch/PR 草稿的只读约束、测试证据要求，以及 CI 日志 Artifact 与分析 prompt 的关联；
- 定向验证命令：`pytest tests/test_git_workflow.py tests/test_cli.py -q`；
- 全量回归命令：`pytest tests -q`，结果为 `310 passed, 2 skipped`。
