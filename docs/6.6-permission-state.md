# 6.6 完整 PermissionState 及权限生命周期说明

6.6 做的是把“工具执行前问不问用户”升级成一套正式权限账本。

在 6.6 之前，项目已经能根据工具 `risk_level` 做确认：高风险和中风险工具会调用 `confirm_tool`，用户拒绝后给模型回填 `User denied tool execution.`。但这个流程只存在于 `AgentLoop` 的局部判断里，状态上只能看到零散的 `permission_requests` 和 `permission_denials`，不知道一次请求是否还在等待、是否已授权、授权作用域是什么、拒绝原因是什么，也无法处理中断后遗留的孤立请求。

所以 6.6 的目标不是改变 CLI 交互方式，而是先建立权限生命周期的正式状态模型：

- 每一次权限申请都有 request id、工具名、参数摘要、风险、作用域、原因、时间和关联 Tool Call；
- 每一次决定都会进入 decisions；
- 拒绝会单独进入 denials，但不会变成永久拒绝；
- session / task 级授权有独立 grant 表；
- 未处理完的 pending request 可以转成 orphaned request；
- 状态可以序列化和恢复，为后续 QueryEngine、权限网关和状态持久化做准备。

一句话概括：6.6 = 给工具权限建立可追踪、可恢复、可扩展的生命周期账本。

## 2. PermissionState 包含什么

位置：`zzm_agent/core/runtime_state.py`

新增状态结构：

```text
PermissionState
├── pending_requests
├── decisions
├── denials
├── session_grants
├── task_grants
├── orphaned_requests
└── has_handled_orphaned_permission
```

这些字段分别表示：

- `pending_requests`：已经发起但尚未得到决定的权限请求；
- `decisions`：所有已经处理过的权限决定；
- `denials`：拒绝历史，用于观察和避免重复申请，但不自动变成永久拒绝；
- `session_grants`：当前会话内有效的授权；
- `task_grants`：当前任务内有效的授权；
- `orphaned_requests`：中断、恢复或清理时发现的孤立请求；
- `has_handled_orphaned_permission`：本状态是否已经做过孤立请求处理。

## 3. 权限状态和作用域

位置：`zzm_agent/core/runtime_state.py`

新增：

- `PermissionStatus`
- `PermissionScope`

权限状态包括：

```text
pending
approved_once
approved_session
approved_task
denied
expired
orphaned
cancelled
```

权限作用域包括：

```text
once
session
task
```

当前 `AgentLoop` 的交互回调仍然只返回布尔值，所以运行时确认成功时记录为 `approved_once`。`PermissionState` 已经支持 `approved_session` 和 `approved_task`，后续 CLI 或 QueryEngine 可以在不改底层状态结构的情况下提供“本次 / 本会话 / 本任务”选择。

## 4. 请求和决定记录

位置：`zzm_agent/core/runtime_state.py`

新增：

- `PermissionRequest`
- `PermissionDecision`

每个 `PermissionRequest` 记录：

- `request_id`
- `tool_name`
- `arguments_summary`
- `risk_level`
- `scope`
- `status`
- `reason`
- `tool_call_id`
- `turn_id`
- `task_id`
- `created_at`
- `updated_at`
- `expires_at`

每个 `PermissionDecision` 记录：

- `decision_id`
- `request_id`
- `tool_name`
- `arguments_summary`
- `risk_level`
- `status`
- `scope`
- `reason`
- `tool_call_id`
- `turn_id`
- `task_id`
- `decided_at`
- `expires_at`

参数摘要由 `summarize_permission_arguments()` 生成，包含稳定 hash 和短预览。这样日志和持久化状态可以判断“这次授权对应哪组参数”，又不会把超长参数完整塞进权限表。

## 5. PermissionState 的关键方法

位置：`zzm_agent/core/runtime_state.py`

关键方法：

- `request_permission(...)`：创建 pending request；
- `approve_request(...)`：把 pending request 转成授权 decision；
- `deny_request(...)`：把 pending request 转成拒绝 decision，并写入 denials；
- `expire_request(...)`：把 pending request 标记为过期；
- `cancel_request(...)`：把 pending request 标记为取消；
- `orphan_request(...)`：把单个 pending request 移入 orphaned；
- `handle_orphaned_permissions()`：一次性处理所有 pending request；
- `find_active_grant(...)`：根据工具名和参数摘要查找有效 session / task 授权；
- `to_record()` / `from_record()`：序列化和恢复完整权限状态。

## 6. RuntimeState 如何接入

位置：`zzm_agent/core/runtime_state.py`

6.6 在运行时状态中接入：

- `TurnState.permissions: PermissionState`
- `ConversationState.permissions: PermissionState`

同时保留旧字段：

- `TurnState.permission_requests`
- `TurnState.permission_denials`

保留旧字段是为了不打断已有测试、CLI 展示和调用方。新的 `PermissionState` 是正式账本，旧字段作为兼容镜像继续存在。

## 7. AgentLoop 如何接入

位置：`zzm_agent/core/agent_loop.py`

`AgentLoop` 新增：

```python
self.permission_state = PermissionState()
```

工具执行链路现在是：

```text
模型返回 tool_calls
  ↓
LoopState 进入 VALIDATING_TOOL_CALLS
  ↓
读取工具 risk_level
  ↓
先查 PermissionState.find_active_grant()
  ↓
没有有效授权且需要确认时：
    LoopState 进入 AWAITING_PERMISSION
    PermissionState.request_permission()
    TurnState.permission_requests 记录兼容副本
  ↓
用户拒绝：
    LoopState 记录 permission_denied
    PermissionState.deny_request()
    TurnState.permission_denials 记录兼容副本
    回填 User denied tool execution.
  ↓
用户同意：
    PermissionState.approve_request(scope=once)
    工具正常执行
```

低风险工具或 `auto_approve=True` 的路径仍然维持旧行为，不额外制造权限请求。
