# 9.4 插件清单（Plugin Manifest）使用说明

## 一句话说明

插件目录就是 Agent 寻找扩展功能的地方。

以前，一个插件通常只是单独的 Python 文件。现在，一个插件也可以是一个完整目录，
把 Python 工具、Skill 和 MCP 配置放在一起，并通过 `plugin.yaml` 告诉 Agent 应该加载
哪些内容。

如果你只使用项目自带工具，不需要创建任何新目录，也不需要编写 Manifest。

## 先看这里：到底修改哪个配置文件

插件目录配置在 YAML 配置文件的 `agent.plugin_dirs` 中。应该修改哪个文件，取决于你
如何运行 zzm-agent。

### 情况一：直接在源码项目中运行

修改项目根目录的 `config.yaml`。

以当前项目为例，Windows 上的完整路径是：

```text
E:\PythonProject\study\zzm-agent\config.yaml
```

配置写在 `agent` 下面：

```yaml
agent:
  plugin_dirs:
    - "zzm_agent/plugins"
    - ".zzm_agent/plugins"
```

这里的相对路径以这个 `config.yaml` 所在目录为基准。因此：

```text
zzm_agent/plugins   -> E:\PythonProject\study\zzm-agent\zzm_agent\plugins
.zzm_agent/plugins  -> E:\PythonProject\study\zzm-agent\.zzm_agent\plugins
```

### 情况二：项目已经打包，并通过 pip 安装

不要修改 Python 安装目录或 `site-packages` 里的文件。正常情况下应修改用户配置：

```text
~/.zzm_agent/config.yaml
```

在当前 Windows 用户下，`~` 表示用户主目录，例如：

```text
C:\Users\zhangzm\.zzm_agent\config.yaml
```

第一次交互运行 `zzm-agent` 时，如果系统没有找到其他配置，程序会自动创建这份用户
配置。打包在程序里的自带插件路径也会自动写入，不需要手工查找 `site-packages`。

建议把自己安装或编写的插件放在：

```text
C:\Users\zhangzm\.zzm_agent\plugins\
```

然后编辑 `C:\Users\zhangzm\.zzm_agent\config.yaml`：

```yaml
agent:
  plugin_dirs:
    # 保留首次运行生成的自带插件绝对路径。
    - "C:/path/to/python/site-packages/zzm_agent/plugins"

    # 在这里添加用户自己的插件目录。
    - "~/.zzm_agent/plugins"
```

第一行的实际路径由程序安装位置决定，应保留自动生成的原值；你通常只需要添加第二
行。Windows 路径推荐在 YAML 中使用 `/`，可以减少反斜杠转义问题。

### 情况三：希望某个项目单独使用一套插件

可以在工作目录创建：

```text
当前工作目录/.zzm_agent/config.local.yaml
```

例如：

```yaml
agent:
  plugin_dirs:
    - "./project-plugins"
```

这个本地配置会与用户配置、项目 `config.yaml` 合并，适合只在当前工作目录启用的
插件。后加载的本地值会覆盖同名配置项；由于 `plugin_dirs` 是列表，覆盖时应把仍需
保留的目录一起写出来。

### 情况四：启动时指定了配置文件

如果使用：

```powershell
zzm-agent --config D:/agent-config/config.yaml
```

或者：

```powershell
$env:ZZM_AGENT_CONFIG = "D:/agent-config/config.yaml"
zzm-agent
```

那么插件目录就在这份指定的 `config.yaml` 中配置。此时相对路径以
`D:/agent-config/` 为基准，并且程序不会再自动合并默认位置的配置。

### 快速选择

| 运行方式 | 应修改的配置文件 | 自定义插件建议放置位置 |
| --- | --- | --- |
| 在源码仓库开发 | `<项目根目录>/config.yaml` | `<项目根目录>/.zzm_agent/plugins` |
| pip 安装后日常使用 | `~/.zzm_agent/config.yaml` | `~/.zzm_agent/plugins` |
| 只给当前工作目录使用 | `<工作目录>/.zzm_agent/config.local.yaml` | `<工作目录>/.zzm_agent/plugins` |
| 使用 `--config` | 命令指定的配置文件 | 任意目录，在该配置中填写 |

## 当前插件保存在哪里

项目自带插件位于：

```text
zzm_agent/plugins/
├── file_ops.py
├── search.py
└── shell.py
```

在源码仓库中，项目当前通过根目录 `config.yaml` 的下面这段配置加载它们：

```yaml
agent:
  plugin_dirs:
    - "zzm_agent/plugins"
```

需要注意，`.zzm_agent` 目录默认主要保存 Skill、会话状态、记忆和运行产物，并不是
默认的 Python 插件目录：

```text
.zzm_agent/
├── skills/
├── state/
├── artifacts/
└── memory.json
```

如果希望把当前源码项目的私人插件放进 `.zzm_agent/plugins`，需要主动添加配置：

```yaml
agent:
  plugin_dirs:
    - "zzm_agent/plugins"       # 项目自带插件
    - ".zzm_agent/plugins"      # 当前项目的私人插件
```

插件也可以放在其他位置，例如用户公共目录或其他磁盘：

```yaml
agent:
  plugin_dirs:
    - "zzm_agent/plugins"
    - "~/.zzm_agent/plugins"
    - "D:/my-agent-plugins"
```

相对路径以 `config.yaml` 所在目录为基准。

## 这次新增了什么

原来的单文件插件仍然可以使用：

```text
my-plugins/
└── my_tool.py
```

现在还支持“插件包”：

```text
my-plugins/
└── browser-plugin/
    ├── plugin.yaml
    ├── tools.py
    └── skills/
        └── browser-debug/
            └── SKILL.md
```

其中：

- `plugin.yaml`：说明插件叫什么、加载什么以及默认是否启用。
- `tools.py`：插件提供的 Python 工具，可以省略。
- `skills/`：插件附带的 Skill，可以省略。
- MCP 服务不需要放在单独文件里，可以直接在 `plugin.yaml` 中配置。

因此，9.4 的核心变化不是“第一次支持其他插件目录”，而是支持把相关功能组成一个
完整插件包，并统一加载或关闭。

## 最简单的插件示例

先创建目录：

```text
.zzm_agent/plugins/
└── hello-plugin/
    ├── plugin.yaml
    └── tools.py
```

`plugin.yaml`：

```yaml
name: hello-plugin
version: 1.0.0
description: 提供一个问候工具
entry: tools.py
```

`tools.py`：

```python
from zzm_agent.core.tool_registry import tool


@tool(description="返回一段问候语")
def hello(name: str) -> str:
    return f"你好，{name}！"
```

然后在 `config.yaml` 中加入插件目录：

```yaml
agent:
  plugin_dirs:
    - "zzm_agent/plugins"
    - ".zzm_agent/plugins"
```

重新启动 Agent 后，`hello` 就会进入工具注册表。

## 同时打包 Skill 和 MCP

一个插件可以只提供某一种能力，也可以同时包含工具、Skill 和 MCP：

```yaml
name: browser-plugin
version: 1.0.0
description: 浏览器操作与网页调试
enabled: true

# 可选：加载 Python 工具
entry: tools.py

# 可选：加载插件目录中的 Skills
skills:
  - skills

# 可选：启动 stdio MCP 服务
mcp:
  servers:
    - name: chrome
      command: [npx, "-y", "chrome-mcp-server"]
      timeout_seconds: 15

# 可选：说明插件可能需要哪些能力
permissions:
  network:
    connect: [localhost]
  subprocess: true
```

Agent 启动时会：

1. 读取并检查 `plugin.yaml`。
2. 加载 `tools.py` 中的工具。
3. 把插件的 `skills` 目录加入 Skill 搜索范围。
4. 使用已有的 MCP 客户端启动 `chrome` 服务。
5. 让插件工具继续经过原有的参数检查、权限确认、超时和审计流程。

当前 MCP 客户端只支持 stdio。Streamable HTTP、SSE 和 WebSocket 在后续规划中。

## 如何关闭或重新启用插件

可以在 `config.yaml` 中关闭整个插件：

```yaml
plugins:
  browser-plugin:
    enabled: false
```

关闭后，Agent 不会：

- 导入这个插件的 Python 代码；
- 加载这个插件的 Skills；
- 启动这个插件声明的 MCP 服务。

重新启用：

```yaml
plugins:
  browser-plugin:
    enabled: true
```

这里的 `browser-plugin` 必须与 `plugin.yaml` 中的 `name` 一致。修改启停配置后需要
重新启动 Agent。

## 权限声明是什么意思

插件可以写下自己可能需要的能力：

```yaml
permissions:
  filesystem:
    read: [workspace]
    write: []
  network:
    connect: [api.example.com]
  subprocess: true
  secrets: [EXAMPLE_TOKEN]
```

这些内容相当于插件的“能力说明书”，方便用户检查和后续界面展示，并不代表 Agent
已经批准这些操作。

即使插件声明了权限，它仍然不能：

- 自动批准中风险或高风险工具；
- 读写 Workspace 以外的文件；
- 把密钥值自动发送给模型；
- 绕过 MCP 工具的参数检查、超时和权限确认。

插件中的 Python 代码会在当前 Agent 进程中运行，所以只应加载你信任的本地插件。

## 支持哪些 Manifest 文件

一个插件包可以使用以下任意一种文件名：

- `plugin.yaml`：推荐。
- `plugin.yml`：支持。
- `plugin.json`：用于兼容原有插件。

同一个插件目录只能存在其中一个，否则 Agent 会拒绝加载，避免无法确定应该使用哪份
配置。

`entry` 和 `skills` 必须指向插件目录内部，不能使用 `../` 访问插件外部文件。某一个
插件格式错误时，只会记录该插件的错误，不会阻止其他插件启动。

## 当前还没有实现什么

9.4 是插件加载基础，并不是完整的插件商店。目前还没有：

- 插件下载和一键安装；
- 卸载、升级和失败回滚；
- 插件签名和来源验证；
- 图形化插件管理页面；
- 完整的 Python 插件进程隔离。

下一项 9.5 会重点改善终端展示，让用户能更直观地看到插件、Skill 和 MCP 的来源、
状态、启用原因及错误信息。
