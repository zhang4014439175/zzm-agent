# 8.11 Secret Redaction 与内容信任标签基础

## 1. 一句话说明

在运行事件、工具日志和模型上下文出口统一遮蔽常见密钥，并把外部工具结果默认标记为不可信内容。

## 2. 为什么需要它

工具参数、错误消息、Provider 事件和网页结果可能包含 API Key、Token、密码或私钥。如果这些值直接进入 JSONL、RuntimeEvent、调试日志或下一轮模型上下文，就会扩大凭据泄露范围。与此同时，工具返回的网页、CI 和日志内容不能与系统指令拥有相同信任级别。

## 3. 一个实际使用例子

用户让 Agent 调用工具，工具错误中包含：

    Authorization: Bearer abcdefghijklmnop

写入 ToolEvent 或 RuntimeEvent 时，实际记录变为：

    Authorization: Bearer [REDACTED]

工具结果同时携带 content_source=工具名 和 content_trust=untrusted；即使旧插件没有主动设置标签，也会获得安全默认值。

## 4. 功能的大致流程

1. 工具或 Provider 产生参数、结果和错误内容。
2. security.content 递归识别敏感字段和文本凭据模式。
3. RuntimeEvent、ToolEvent 与 ToolResult 在序列化出口执行脱敏。
4. ToolResult 在返回模型消息前再次脱敏。
5. ToolResult 记录内容来源和信任级别，供后续 Prompt Injection 策略使用。

## 5. 开发前和开发后的区别

开发前只有长度截断和局部配置遮蔽，Token 仍可能进入事件 payload、工具预览和模型消息，工具结果也没有统一信任标签。开发后这些出口共享同一递归脱敏器，外部工具结果默认 untrusted，旧记录恢复时也会补齐安全默认值。

## 6. 现在已经支持的能力

- 按敏感字段名递归遮蔽字典、列表和元组。
- 识别 Bearer Token、常见 key=value 凭据、OpenAI 风格密钥和私钥块。
- RuntimeEvent 序列化前脱敏 payload。
- ToolEvent 参数摘要、结果预览和错误消息脱敏。
- ToolResult 模型消息和持久化记录脱敏。
- ToolResult 记录 content_source 和 content_trust。
- 旧 ToolResult 记录默认恢复为 untrusted。

## 7. 当前限制（还做不到什么）

本任务提供的是安全基础，不包含完整 Prompt Injection 检测、网页/MCP 沙箱、组织级策略和安全事件审计。脱敏依赖字段名与凭据模式，无法保证识别所有自定义格式；15.1 将继续完成外部内容隔离和策略执行。

## 8. 给开发者看的实现位置

- zzm_agent/security/content.py：递归脱敏、ContentTrust 和来源元数据。
- zzm_agent/runtime/events.py：RuntimeEvent 序列化出口。
- zzm_agent/core/observability.py：工具日志与预览出口。
- zzm_agent/core/tool_results.py：工具结果信任标签和模型消息出口。
- tests/test_content_security.py：敏感字段、文本凭据、事件和兼容记录测试。

## 9. 测试如何证明它有效

定向测试使用真实形态的 API Key、Bearer Token、password 字段和工具输出，验证原值不会出现在事件、日志记录和模型消息中；同时验证新旧 ToolResult 都具有 untrusted 默认标签，并确认安全文本不会被误删。
