# 8.4A 阶段验收：长任务持续执行

## 一句话说明

8.4A 阶段已经证明：长工具任务不会因空回复或单段轮次耗尽而静默结束，系统会恢复、压缩并自动续跑，或者明确说明阻塞原因；简单任务仍保持一次模型调用完成。

## 为什么需要它

单项测试只能说明某个组件工作。用户遇到的问题发生在完整链路：大量工具输出、上下文增长、模型空回复、单段上限和终端结束提示共同作用。阶段验收必须把这些能力串起来验证。

## 一个实际使用例子

验收用例让工具生成一份超长报告，并把每段工具轮次限制为 1。第一段将完整报告保存为 Artifact，生成检查点；QueryEngine 计算下一段预算并压缩历史，然后自动继续。

第二段读取带来源的摘要并给出最终结论。整个过程中用户只提交一次请求。另一个用例模拟 Provider 因长度返回空内容，系统在同一段恢复；重复工具调用用例则确认安全熔断仍会阻塞。

## 功能的大致流程

1. 构造包含超长工具输出和严格单段边界的固定场景。
2. 验证完整输出进入 Artifact，模型上下文只保留轻量引用。
3. 验证第一段状态为 `yielded`，检查点包含 Artifact、轮次和剩余工作。
4. 验证 QueryEngine 为下一段计算压缩额度，产生压缩摘要并自动调用模型。
5. 验证最终状态为 `completed`，用户无需手动输入继续。
6. 单独模拟 Provider 截断后的空回复，确认恢复后完成并保留 finish reason 历史。
7. 单独模拟重复调用，确认它仍以 `blocked` 结束。
8. 运行完整测试套件，确认简单任务、权限、取消、CLI、Replay 和旧功能没有回归。

## 开发前和开发后的区别

开发前：单段轮次耗尽就是整个任务阻塞；大工具结果持续进入上下文；QueryEngine 不理解内部让出。

开发后：单段边界、任务终止和完成判定分离。长任务能够自动换段，空回复有恢复或明确阻塞，所有最终状态都有原因。

## 现在已经支持的能力

- 长工具结果 Artifact 化并保留校验来源。
- 工具轮次和上下文边界安全让出。
- 检查点持久化、上下文压缩和自动续段。
- Provider 截断空回复恢复。
- 重复循环、失败、权限和取消安全边界保持有效。
- 简单任务不增加续段或 Planner 调用。

## 当前限制（还做不到什么）

- 阶段验收验证的是运行协议，不证明模型对任意大型开发任务都能做出正确代码修改。
- 完成状态尚未逐项核对正式计划和测试证据。
- 跨进程无人值守恢复、并行子任务和完整 TaskRunner 仍属于后续路线图。
