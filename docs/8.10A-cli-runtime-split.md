 # 8.10A CLI Runtime 拆分

## 1. 一句话说明

把原来集中在 `cli_support/runtime.py` 的启动装配、交互式 REPL 和非交互执行拆成三个职责清晰的模块，并移除旧的兼容入口。

## 2. 为什么需要它

旧 `runtime.py` 同时负责参数解析、配置加载、依赖装配、状态栏、错误格式化、REPL 输入循环和 `exec` 输出协议。修改任意一处都需要理解整份大文件，也容易让 CLI 绕过 `QueryEngine` 直接协调 `AgentLoop`。拆分后，每种运行方式有明确入口，后续继续拆 Slash Command 和 Renderer 时不会再次把职责堆回一个文件。

## 3. 一个实际使用例子

用户仍然可以运行：

```powershell
zzm-agent exec --json "读取 README.md 并概括项目用途"
```

`bootstrap.py` 解析配置并装配运行时，`execution.py` 把请求提交给 `QueryEngine`，随后逐行输出统一 `RuntimeEvent` 和最终结果。

## 4. 功能的大致流程

1. `bootstrap.py` 解析命令行、加载配置并创建 `QueryEngine` 等运行对象。
2. `exec` 命令进入 `execution.py`，REPL 命令进入 `repl.py`。
3. 两种执行入口都通过 `QueryEngine.submit_message()` 提交用户请求。
4. `execution.py` 将统一运行事件编码成 JSONL；`repl.py` 将流事件交给终端 Renderer。

## 5. 开发前和开发后的区别

开发前，`runtime.py` 超过一千行，启动、执行和交互逻辑互相引用，REPL 还会在缺少 `QueryEngine` 时直接调用 `loop.run()`。开发后，启动装配位于 `bootstrap.py`，单次执行位于 `execution.py`，交互循环位于 `repl.py`；新的 REPL 必须获得 `QueryEngine`。

## 6. 现在已经支持的能力

- 启动配置、首次运行引导和运行时装配集中在 `bootstrap.py`。
- `exec` 的 prompt、JSONL、输出文件和错误出口集中在 `execution.py`。
- REPL 状态栏、错误提示、输入循环和流式展示集中在 `repl.py`。
- REPL 与非交互执行统一通过 `QueryEngine` 处理请求。
- PowerShell、Bash 和 Zsh 补全脚本仍由启动模块提供。

## 7. 当前限制（还做不到什么）

Slash Command 的解析和业务逻辑仍集中在 `cli_support/commands.py`，Renderer 与输入组件也仍集中在 `cli_support/rendering.py`。它们分别由后续 8.10B 和 8.10C 完成，本任务不提前改变其业务边界。

## 8. 给开发者看的实现位置

- `zzm_agent/cli_support/bootstrap.py`：参数、配置、依赖装配与 CLI 主入口。
- `zzm_agent/cli_support/execution.py`：非交互任务和 JSONL 输出。
- `zzm_agent/cli_support/repl.py`：交互循环、状态反馈和错误格式化。
- `tests/test_cli_runtime_split.py`：模块归属和依赖边界测试。

## 9. 测试如何证明它有效

`tests/test_cli_runtime_split.py` 验证三个核心入口确实归属不同模块，且执行与 REPL 不直接导入 `AgentLoop`。原有 `tests/test_cli.py` 和 `tests/test_p2_acceptance.py` 继续验证参数解析、首次配置、工具确认、REPL、流式输出和 JSON 事件没有回归；全量测试用于证明拆分没有影响核心运行链路。
