# 8.7 AgentLoop 职责拆分

## 目标

在不改变 CLI、Replay、工具权限和消息持久化行为的前提下，把 `AgentLoop` 中四类可独立测试的职责提取为组件，使 `AgentLoop` 收敛为单个 Segment 的状态编排器。

## 完成内容

- `ModelTurnDriver`：负责非流式/流式模型请求、Provider 降级、内容与 reasoning 事件解析、Usage 采集及工具调用增量组装。
- `ToolCallCoordinator`：负责风险确认、PermissionState 同步、Registry 兼容调用、取消检查和结构化错误的有限重试。
- `RecoveryPolicy`：集中生成重复调用、轮次上限、无进展停止和一次性反思提示，并计算有上限的重试退避。
- `ContextPreparationService`：统一构建系统提示、工具 Schema 预算、输出预留、Prompt Cache 策略、压缩上下文和运行时临时指令。
- `AgentLoop`：保留 Turn/Loop 生命周期、Hook、Usage、ProgressMonitor、工具轮次顺序和 Segment 终止状态编排；原私有入口继续委托新组件，避免破坏现有调用者。

## 边界与取舍

本任务只移动既有职责，没有新增产品行为。`ToolRegistry` 的目录化不属于 8.7；本次只把执行边界交给 `ToolCallCoordinator`。运行时状态对象的文件拆分属于后续 8.8，Workspace 副作用统一属于 8.9。

运行时临时指令仍只进入当前 `ConversationMessageStore.runtime_messages`，不会写入持久历史。上下文服务返回预算事实供 `AgentLoop` 在每轮模型调用前动态核算，不把状态机逻辑移入上下文组件。

## 兼容性

- `_complete_once`、`_stream_once`、权限记录、重试、恢复文案和 `_build_system_prompt` 等原入口保留并委托新组件。
- 支持原生 `cancellation_token` 的 Registry 继续直接接收取消令牌；旧 Registry 仍在调用前后检查取消。
- 流式事件顺序、Tool Call 记录格式、Replay 输出和结构化错误格式保持不变。

## 验收

- 新增组件级测试，覆盖模型驱动委托、上下文预算与消息分层、权限确认、可恢复错误重试和恢复策略。
- 运行 AgentLoop 与 Replay 定向回归。
- 运行完整测试套件。
- `git diff --check` 无格式错误。
