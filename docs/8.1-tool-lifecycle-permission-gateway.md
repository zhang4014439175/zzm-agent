# 8.1 工具生命周期、参数校验与权限网关

## 一句话说明

这项能力确保任何注册工具在真正运行之前都必须先通过同一套参数 schema 校验，再进入风险分级和权限确认；无效调用不会触发工具副作用，也不会浪费一次用户授权。

## 解决的问题

此前 ToolRegistry 会生成 JSON Schema 给模型，但执行时只是把参数直接传给 Python 函数。Schema 因此更像提示而不是强制边界：缺少参数、错误类型或模型虚构的额外参数只能依靠 Python 抛出 TypeError；如果工具风险较高，AgentLoop 还可能先向用户请求批准，随后才发现参数根本不能执行。

这种行为对内置工具、插件工具和未来 MCP 适配器都不安全。参数错误必须在进入工具函数前被确定性阻断，权限确认只应面对一个结构合法、可明确审计的调用。

## 具体例子

模型请求一个高风险工具：

```json
{"name": "wipe", "arguments": {"target": 123}}
```

而 `target` 的 schema 类型是字符串。新链路会在 BEFORE_TOOL hook 完成参数修改后调用 `validate_arguments()`；校验发现 integer 与 string 不匹配，生成 `ToolArgumentValidationError`，不调用确认回调、不发出 `tool.start`、也不进入 `wipe()`。随后 `tool.error` 事件和结构化错误 Observation 告诉模型重新生成符合 schema 的参数。

## 使用场景

- 模型生成遗漏必填字段或错误 JSON 类型时；
- 模型传入工具签名中不存在的额外字段时；
- BEFORE_TOOL hook 修改参数后需要重新验证时；
- 内置、传统插件、manifest 插件以及未来 MCP 工具通过 ToolRegistry 执行时；
- 高风险工具需要确认前，保证用户看到的参数就是实际可执行参数。

## 执行链路

```text
模型 tool call
  -> JSON 解析
  -> BEFORE_TOOL hook（可修改参数）
  -> ToolRegistry.validate_arguments()
     -> required / additionalProperties / JSON type 校验
  -> 风险级别读取
  -> PermissionState / confirm_tool
  -> tool.start
  -> ToolRegistry.call()（再次执行不可绕过校验）
  -> Python 工具函数
  -> tool.end 或 tool.error
  -> ToolResult / Observation / EventBus 消费链路
```

## 关键事件或数据结构

- 工具参数 schema：注册时生成 `type=object`、properties、required 和 `additionalProperties=false`；
- `ToolArgumentValidationError`：保存工具名和全部校验问题，属于确定性的 argument 类错误；
- `ToolError(error_type="ToolArgumentValidationError")`：模型可读的结构化失败，提示重新生成参数且不要重复请求权限；
- `tool.start`：只在参数有效且权限通过后发出；
- `tool.error`：参数校验失败时包含专用错误类型和详细原因；
- `tool.end`：记录成功或权限拒绝结果，保持现有回放协议。

## 代码定位

- `zzm_agent/core/tool_registry.py`
  - `ToolArgumentValidationError`：专用参数校验异常；
  - `ToolRegistry.validate_arguments()`：校验必填项、未知字段和 JSON 类型；
  - `ToolRegistry.call()`：统一不可绕过的校验与执行入口；
  - `_matches_json_type()`：无隐式类型转换的 JSON 类型判断；
- `zzm_agent/core/agent_loop.py`
  - 在 BEFORE_TOOL hook 后、权限请求前执行参数校验；
  - 继续通过现有权限账本、确认回调和工具事件链执行合法调用；
- `zzm_agent/core/errors.py`
  - `tool_error_from_exception()` 保留专用校验错误语义。

## 边界与非目标

- 本阶段校验当前注册器生成的基础 JSON 类型，不实现完整 JSON Schema Draft；
- 不递归校验数组 items、对象嵌套 properties、enum、pattern 或数值范围；
- 不做字符串到数字、数字到布尔值等隐式转换；
- 文件路径和网络域名是否允许属于 8.2 沙箱 Profile；
- 超时、强制取消和资源清理属于 8.3；
- 未来 MCP 工具必须先注册到或适配这个网关，本阶段不实现 MCP Client。

## 测试与验证

- `tests/test_tool_registry.py`
  - 无效参数不会进入工具函数；
  - 缺少必填项、类型错误和额外参数均被拒绝；
  - boolean 不被当作 integer，number 接受整数或浮点数；
  - schema 明确声明 `additionalProperties=false`；
- `tests/test_agent_loop.py`
  - 高风险无效参数在确认前失败；
  - 不执行函数、不触发确认、不发出 `tool.start`；
  - 发出专用 `ToolArgumentValidationError` 的 `tool.error`。

定向验证命令：

```text
pytest tests\test_tool_registry.py tests\test_agent_loop.py -q
```

最终定向回归（含既有错误恢复契约）：`56 passed`。

全量验证命令：

```text
pytest tests -q
```

全量结果：`317 passed, 2 skipped`。
