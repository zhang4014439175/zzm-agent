# 8.2 文件系统与网络沙箱 Profile

## 一句话说明

这项能力用一个统一的 SandboxProfile 决定 Agent 可以读写哪些本地路径、可以访问哪些网络目标；默认只允许工作区内文件操作、拒读敏感文件，并关闭网络访问。

## 解决的问题

此前文件和搜索插件各自实现“路径不能逃出单个工作区”的检查，但规则重复且不完整：`.env`、`.ssh`、云凭据目录仍可能被直接读取；无法配置多个 workspace root 或显式 deny 路径；未来网络工具也没有默认关闭、域名 allow/deny、localhost 和私网边界。

分散判断容易产生旁路。一个插件修复了符号链接逃逸，另一个插件可能仍按字符串前缀判断。SandboxProfile 把路径规范化、真实父目录解析、敏感路径、显式拒绝和网络目标判断收敛为核心策略。

## 具体例子

当工作区是 `D:\project` 时，模型请求 `read_file(".env")`。路径虽然位于工作区内，但 Profile 发现路径组成部分命中 `.env`，返回 `SandboxViolation`，不会把 API Key 放入模型上下文。模型只能报告拒绝并请求受控 Profile 变更，不能换一个相对路径重试绕过。

网络侧默认 `network_enabled=false`。即使未来工具请求 `https://api.example.com` 也会被拒绝；管理员显式开启网络并设置 `example.com` allowlist 后，其子域名可访问，但 `localhost`、`127.0.0.1`、`192.168.0.0/16` 等目标仍需分别授权。

## 使用场景

- 文件读取、元信息查看、内容搜索和文件名搜索；
- 文件创建、覆盖、追加和精确编辑；
- monorepo 或多根工作区的路径授权；
- 明确禁止项目中的私密子目录；
- 未来 HTTP/MCP/浏览器工具发起网络连接前；
- Windows、WSL、macOS/Linux 上处理绝对路径、符号链接和特殊位置。

## 执行链路

```text
工具参数
  -> SandboxProfile.from_environment()
  -> authorize_path(path, read|write)
     -> 展开相对路径 -> 解析真实路径/最近真实父目录
     -> workspace roots -> explicit deny -> sensitive read
  -> 文件或搜索插件执行

网络 URL
  -> authorize_url(url)
  -> scheme -> network enabled -> deny domains
  -> localhost/loopback -> private/link-local -> allow domains
  -> 网络工具执行（未来接入）
```

## 关键事件或数据结构

- `SandboxProfile`：不可变策略对象，保存 workspace roots、deny paths、敏感名称和网络规则；
- `SandboxViolation`：确定性的 permission 类拒绝；结构化错误提示请求受控 Profile 变更或显式升级；
- `ZZM_AGENT_WORKSPACE_ROOTS`：使用操作系统 path separator 配置多个根；
- `ZZM_AGENT_DENY_PATHS`：配置绝对 deny 路径；
- `ZZM_AGENT_ALLOW_SENSITIVE_READ`：显式允许敏感读取，默认关闭；
- `ZZM_AGENT_NETWORK_ENABLED`、`ZZM_AGENT_NETWORK_ALLOW_DOMAINS`、`ZZM_AGENT_NETWORK_DENY_DOMAINS`；
- `ZZM_AGENT_ALLOW_LOCALHOST`、`ZZM_AGENT_ALLOW_PRIVATE_NETWORK`。

## 代码定位

- `zzm_agent/core/sandbox.py`
  - `SandboxProfile.from_environment()`：构造当前运行 Profile；
  - `authorize_path()`：文件读写策略；
  - `authorize_url()`：网络目标策略；
- `zzm_agent/plugins/file_ops.py`：所有 read/write/edit/append/list/info 操作复用 Profile；
- `zzm_agent/plugins/search.py`：搜索入口和逐文件读取复用 Profile；
- `zzm_agent/core/errors.py`：把 SandboxViolation 转成结构化权限错误。

## 平台差异

- Windows 使用盘符和反斜杠，`Path.resolve()` 负责大小写/规范化语义；多根列表使用 `os.pathsep`（Windows 为分号）；
- Unix/WSL 使用 `/` 和冒号分隔多根；符号链接按真实目标判断，链接目标逃出根目录会被拒绝；
- Unix socket、命名管道和设备路径不是普通 HTTP(S) URL，本阶段网络授权 API 直接拒绝非 HTTP(S) scheme；
- Profile 是应用层确定性边界，不等同于 OS 容器。Shell 命令仍属于高风险工具并要求权限；真正的进程级 OS 沙箱需要平台专用执行器。

## 边界与非目标

- 本阶段没有新增网络工具，只提供未来工具不可绕过的授权 API；
- 不解析 DNS 后再检查地址，避免策略检查自身产生网络副作用；网络执行器后续必须防 DNS rebinding；
- Shell 命令内容无法仅靠 Path API 完整解析，仍由高风险权限控制；
- 沙箱拒绝不会自动降低安全策略，只返回可审计的受控升级建议；
- 超时、取消和子进程清理属于 8.3。
