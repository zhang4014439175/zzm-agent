# 9.3 工具 Schema 按需装载与 Tool Search

## 目标

工具注册和工具暴露现在是两个不同概念：Registry 继续持有完整工具及其执行入口，
模型请求只携带当前任务需要的 Schema。这样大型 MCP Server 可以完成工具发现而
不把全部输入 Schema 固定塞进每次模型调用，同时不改变参数校验、风险分级、人工
确认、超时、Artifact 和审计链路。

## 暴露策略

`ToolExposureManager` 把工具分为两类：

- 本地及未声明延迟加载的工具保持常驻，兼容已有插件和 Agent 行为。
- MCP Client 注册的工具带有 `source=mcp`、Server 名和 `lazy_schema=true`，默认
  只进入轻量目录，不进入模型请求。

延迟工具可由以下入口启用：

1. 用户在任务中显式选择完整标识，例如 `@mcp:github.search_issues`。
2. 当前任务中有足够明确的名称或说明关键词。
3. 已激活 Skill 的 `allowed_tools` 声明命中唯一工具。
4. 模型调用常驻的低风险 `tool_search(query, source, limit)`，命中 Schema 从下一次
   模型调用开始可见。
5. QueryEngine 自动续段时保留上一段已经启用的工具，并记录
   `stage:continuation` 原因。

模型兼容层输出文本伪工具调用时也会检查工具是否已经暴露，不能通过手写内部工具
名访问隐藏 Schema。`tool_search` 只改变可见目录，不调用目标工具；目标 MCP 工具
仍是 medium 风险并经过现有权限网关。

## 会话框前缀

- `$查询` 仍然只模糊搜索本地 Skills。
- `@mcp:查询` 只搜索 MCP 工具，支持服务名与工具名的子序列匹配。
- MCP 候选显示 `MCP · Server · 描述`，选中后插入完整公共标识，但不会立即执行。
- 普通 `@` 提及、环境变量或 `$Skill` 不会混入 MCP 菜单。

## 状态与预算

`ToolExposureState` 记录 `available`、`exposed`、`hidden`、激活原因、搜索词、完整
Schema 成本、实际暴露成本和节省 Token。`ContextPreparationService` 把该记录写入
上下文诊断，`TurnState` 将其序列化到检查点；AgentLoop 每轮模型调用前刷新 Schema
和预算，因此模型搜索后的变化能在同一 Segment 生效。

## 代码位置

- `zzm_agent/core/tool_exposure.py`：目录搜索、选择、状态和 Schema 视图。
- `zzm_agent/core/tool_registry.py`：工具来源、Server 和延迟暴露元数据。
- `zzm_agent/core/context_preparation.py`：任务、Skill 与 Schema 预算组装。
- `zzm_agent/core/agent_loop.py`：循环内刷新及隐藏工具调用拦截。
- `zzm_agent/cli_support/ui/legacy.py`：`@mcp:` 会话补全。
- `zzm_agent/core/state/turn.py`：暴露状态持久化与恢复。

上下文组件定向回归共 `24 passed`；Replay/Eval 回归 `9 passed`；全量测试
`416 passed, 2 skipped`；`compileall` 与 `git diff --check` 均通过。
