# 8.5 Token Budget、自动压缩与上下文解释

## 一句话说明

系统现在会解释一次模型调用的上下文额度分别花在什么地方，并为模型输出预留空间。超长工具结果会保存为 Artifact（完整结果文件），模型只接收摘要、关键片段和可追溯引用；历史过长时则自动压缩，同时保留来源信息。

## 为什么需要它

以前只有历史消息会参与压缩，工具定义、工具结果和输出预留没有进入同一份预算。同一轮长任务不断执行读取、搜索或 Shell 后，工具输出会原样堆入上下文，既容易超限，也无法解释额度被什么内容占用。

简单截断也不安全。模型可能看到半段日志，却不知道完整内容在哪里。本功能把完整内容保存下来，并在轻量上下文中留下摘要、首尾片段、校验值和 Artifact 编号。

## 一个实际使用例子

用户要求 Agent 运行测试并分析一份数万行日志。工具返回结果超过 `agent.max_inline_tool_result_tokens` 后，系统把完整日志保存为一个 Artifact。模型收到的是日志摘要、开头和结尾的关键片段，以及 `artifact-...` 引用。

如果后续消息接近上下文上限，旧工具轮次会压缩成运行时摘要。用户执行 `/status` 可以看到 system prompt、指令文件、记忆、固定事实、历史、工具结果、工具定义、运行时控制和输出预留分别使用了多少估算 token，也能看到 Artifact 等来源。

## 功能的大致流程

1. 任务开始时，系统统计系统提示、项目指令、记忆、固定事实、历史、当前输入、工具定义、运行时指令和输出预留。
2. 系统先扣除不能随意删除的内容，再把剩余额度分配给历史消息。
3. 历史超过剩余额度时，较早内容变成带来源的摘要，近期消息和固定事实继续保留。
4. 工具完成后，系统估算结果大小。结果较小时原样回填；结果过大时完整保存为 Artifact。
5. 模型只接收有界的摘要、关键片段、大小、校验值和 Artifact 引用，终端仍可通过 Artifact 查看完整内容。
6. 每次模型调用前重新计算实际上下文。单段内继续增长到边界时，交给安全让出和自动续段处理。
7. `/status` 展示最近一次预算分区、压缩策略、Prompt Cache（提示缓存）策略和事实来源。

## 开发前和开发后的区别

开发前：历史压缩与工具循环彼此独立；大工具结果完整进入模型上下文；上下文统计只显示消息和工具定义总量。

开发后：所有主要来源进入统一预算；输出空间提前预留；大结果自动 Artifact 化；自动压缩和 `/status` 都能解释内容来源。

## 现在已经支持的能力

- 预算分区覆盖 system prompt、指令文件、记忆、pinned context、历史、工具结果、当前输入、工具 schema、运行时/反思提示和输出预留。
- 通过 `agent.max_inline_tool_result_tokens` 控制工具结果进入 Artifact 的阈值，默认 2000。
- Artifact 保存完整文本、大小、摘要、SHA-256 校验值、会话、Turn 和工具调用信息。
- 模型上下文只保留摘要、首尾关键片段和 Artifact 引用。
- 压缩摘要、固定事实和 Artifact 引用带有来源说明。
- 支持 `provider_native` 与 `stable_prefix` 两种提示缓存策略说明。
- `/status` 展示额度分区、压缩方式和上下文来源。

## 当前限制（还做不到什么）

- 当前 token 数量仍由模型 tokenizer、tiktoken 或字符估算降级链计算，可能与 Provider 最终计费略有差异。
- Artifact 自动摘要目前是确定性的文本摘要和首尾片段，不会额外调用模型提炼语义。
- 当前只自动处理 AgentLoop 结构化工具结果，未来 MCP 和后台任务需要接入同一策略。
- Prompt Cache 策略目前负责稳定前缀和能力说明，不主动绑定某家 Provider 的专用缓存参数。

## 给开发者看的实现位置

- `zzm_agent/core/context_budget.py`：定义预算分区与可序列化报告。
- `zzm_agent/memory/store.py`：计算各来源额度、压缩历史并记录事实来源。
- `zzm_agent/core/agent_loop.py`：预留工具 schema 和输出额度，Artifact 化大结果并在调用前检查预算。
- `zzm_agent/core/runtime_records.py`：保存和读取完整 Artifact。
- `zzm_agent/cli_support/commands.py`：在 `/status` 中解释预算和来源。
- `config.yaml`：提供工具结果阈值和续段安全配置示例。

## 测试如何证明它有效

测试覆盖预算分区求和、输出预留、Provider 缓存能力、大工具结果完整落盘、模型只接收轻量引用、压缩摘要和 `/status` 来源展示。相关针对性回归 `213 passed`，完整回归 `348 passed, 2 skipped`。
