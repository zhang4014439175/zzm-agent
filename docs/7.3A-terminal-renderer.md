# 7.3A 终端输出分层与可降级渲染

## 这项功能是做什么的

7.3A 把终端输出从“直接 print 文本块”升级为“消费结构化事件再渲染”。它解决的是思考摘要、工具执行、正文增量和最终总结混在一起的问题，让用户能一眼区分过程和结论。

没有这项能力时，流式输出只关心 `CONTENT_DELTA`，`reasoning_summary`、`tool_call_delta`、`tool_result`、`final_message` 等事件没有统一展示边界，后续 `exec --json`、异步 TUI 和桌面端也难以复用同一套展示语义。

## 具体例子

模型流事件如下：

```text
reasoning_summary: checking files
tool_call_delta: rg pattern
content_delta: draft
final_message: final answer
```

无 Rich 环境输出：

```text
Reasoning: checking files
Running rg pattern
---
final answer
```

Rich 终端输出会使用更柔和的样式：`Running` / `Ran` 前缀更醒目，参数更弱化，最终总结前有分隔线。

## 功能作用

- 新增 `PlainTextRenderer`，用于无 Rich、非 TTY、管道和测试环境；
- 新增 `TerminalRenderer`，用于交互式 Rich 终端；
- 新增 `build_terminal_renderer()`，根据 console 能力选择渲染器；
- `run_repl()` 的 `on_stream_event` 改为把完整 `ModelStreamEvent` 交给渲染器；
- `CONTENT_DELTA` 仍通过 Markdown 缓冲渲染；
- `FINAL_MESSAGE` 负责输出最终分隔线，避免过程和总结混排；
- 旧的 `on_text_chunk` fallback 仍可用。

## 对应代码文件

- `zzm_agent/cli_support/rendering.py`
  - `PlainTextRenderer`；
  - `TerminalRenderer`；
  - `build_terminal_renderer()`。
- `zzm_agent/cli_support/runtime.py`
  - `run_repl()` 接入事件渲染器。
- `tests/test_cli.py`
  - 渲染器分隔线和降级选择测试。

## 执行链路

```text
QueryEngine.submit_message(..., on_stream_event=...)
→ AgentLoop.run()
→ ModelStreamEvent(status/reasoning/content/tool/final/error)
→ run_repl().on_stream_event()
→ TerminalRenderer 或 PlainTextRenderer
→ 过程区 / 工具区 / 最终总结区分层输出
```

无 Rich / 非 TTY 降级链路：

```text
build_terminal_renderer(console)
→ console 不是 Rich Console，或 console.is_terminal 为 False
→ PlainTextRenderer
→ 输出普通文本，不包含 Rich markup
```

## 关键事件或数据结构

- `ModelStreamEventKind.REASONING_SUMMARY`：思考摘要或推理说明；
- `ModelStreamEventKind.TOOL_CALL_DELTA`：模型正在构造工具调用；
- `ModelStreamEventKind.TOOL_RESULT`：工具执行结果；
- `ModelStreamEventKind.CONTENT_DELTA`：正文增量；
- `ModelStreamEventKind.FINAL_MESSAGE`：最终总结；
- `ModelStreamEventKind.ERROR`：错误输出。

## 边界和非目标

- 7.3A 不做固定底部输入框；
- 7.3A 不实现 Esc 异步取消；
- 7.3A 不把同步 AgentLoop 外包线程改造成伪异步 TUI；
- 工具结果的完整折叠策略继续依赖 `ToolResult` / `RendererRegistry`，本阶段先建立 CLI 事件渲染边界。
