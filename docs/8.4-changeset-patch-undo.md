# 8.4 ChangeSet、Patch 与 `/undo`

## 一句话说明

现在 Agent 修改工作区文件后，会留下可查看的变更记录，并可用 `/undo` 撤销最近一次修改。以前文件被改掉后，用户只能自己回忆旧内容或依赖 Git；现在系统会保存修改前后的内容差异。撤销前还会确认文件没有被你或其他程序继续改过。确认不一致时，它会停止并报告冲突，不会把你的新内容覆盖掉。

## 为什么需要它

让 Agent 写文件很方便，但一次错误替换、一次过大的覆盖写入，都会让人担心“怎么安全地回去”。Git 不一定已初始化，也不一定适合撤销一小次尚未提交的 Agent 修改。

本功能为受管文件写入保留一份可撤销记录。这里的“受管”是指通过 `file_edit`、`write_file` 或 `file_append` 工具完成的工作区文本写入。

## 一个实际使用例子

用户让 Agent“把 `config.yaml` 中的超时从 30 改成 60”。Agent 使用文件编辑工具完成替换。系统先记下文件原来的内容，写入成功后再读取新内容，生成一份差异记录：哪一行从 `30` 变为 `60`，以及这次修改来自哪个工具调用和哪一轮对话。

用户检查后发现要求应当是 45，于是在终端输入 `/undo`。系统先读取当前 `config.yaml`，确认它仍是 Agent 刚刚写出的 `60` 版本。确认通过后，文件恢复为 `30`，终端会显示已撤销的变更集编号。

若用户在此期间手动把文件改成 45，再输入 `/undo`，系统会发现当前文件不再是此前记录的 60 版本。它会报告冲突，保持 45 不动。用户可以按自己的判断继续编辑。

## 功能的大致流程

整个过程分为“记录修改”和“执行撤销”两部分。

1. Agent 准备通过受管工具修改文件时，系统先读取文件并暂存修改前的内容。如果文件原本不存在，也会记住它是本次新建的文件。
2. 工具执行成功后，系统再次读取文件。只有内容确实发生变化时，才会生成一条变更集记录；执行失败或内容没有变化时不会产生无效记录。
3. 变更集会保存修改前后内容的摘要、逐行差异、文件路径，以及这次修改属于哪个工具调用、会话和用户轮次。记录写入工作区的 `.zzm_agent/changesets.json`，程序重启后仍然存在。
4. 用户输入 `/undo` 时，系统选择当前会话最近一条仍然生效的变更；输入 `/undo <changeset-id>` 时，则选择指定变更。
5. 真正恢复前，系统先比较文件当前内容和变更集中的“修改后版本”。两者一致才说明文件没有被继续改动，可以安全撤销。
6. 校验通过后，原本存在的文件恢复为修改前内容；由 Agent 新建的文件会被删除。变更集随后标记为已撤销，防止重复撤销。
7. 如果校验不一致，系统不会修改文件，而是把变更标记为冲突并向用户说明原因。这样可以保住用户或其他程序后来写入的内容。

## 开发前和开发后的区别

开发前：终端的 `/undo` 只是占位提示。文件工具的修改可显示短暂 diff，但没有持久化的撤销记录。

开发后：每次成功且确实改变内容的受管写入都会生成一个 ChangeSet（变更集，即一次完整的可追踪修改记录）。它保留前后内容摘要和可审查 Patch（补丁，即逐行展示删除与新增的文本差异），并可在当前会话用 `/undo` 撤销。

## 现在已经支持的能力

- 记录 `file_edit`、`write_file`、`file_append` 的成功实际改动。
- 保存变更前后 SHA-256 摘要，用于确认文件版本没有变化。
- 保存标准统一 diff，可用于审查具体文本改动。
- 记录工具调用、会话与 Turn（一次用户请求）的关联。
- 使用 `/undo` 撤销当前会话最近一项生效变更；使用 `/undo <changeset-id>` 撤销指定记录。
- 恢复原有文件内容，或在撤销“新建文件”时删除该文件。
- 在重启后从 `.zzm_agent/changesets.json` 重新读取记录。
- 发现文件被后续修改时拒绝撤销并报告冲突。

## 当前限制（还做不到什么）

- 当前仅覆盖内置文本文件写工具；Shell、Git 和未来 MCP 工具的写入尚未纳入 ChangeSet。
- ChangeSet 保存完整的文本快照以便可靠撤销，因此不适合大文件或二进制文件工作流。
- `/undo` 只默认选择当前会话最近一次仍生效的变更，不会自动处理多个互相依赖的历史变更。
- 冲突发生后系统不会尝试自动合并；这是为了避免替用户决定保留哪一段内容。

## 给开发者看的实现位置

- `zzm_agent/core/change_set.py`：`ChangeSetStore` 负责开始时抓取文件旧内容、成功时生成 Patch 并落盘，以及执行摘要校验后的撤销。
- `zzm_agent/cli_support/runtime.py`：把 ChangeSetStore 接入工具开始、成功和失败事件；失败调用只清除临时快照，不产生记录。
- `zzm_agent/cli_support/commands.py`：`_handle_undo()` 解析 `/undo [changeset-id]`，将成功、无记录和冲突以不同终端提示呈现。
- `.zzm_agent/changesets.json`：工作区内保存的 ChangeSet 列表；每条包括文件相对路径、工具/会话/Turn 信息、摘要、Patch、状态和快照。

执行顺序为：工具开始事件 → 保存写前快照 → 工具成功事件 → 比较写后内容并创建 ChangeSet → 用户输入 `/undo` → 摘要校验 → 恢复或安全地报告冲突。

## 测试如何证明它有效

`tests/test_change_set.py` 覆盖：Patch 与前后摘要、会话和 Turn 记录、重启后读取、恢复已有文件、撤销新建文件、外部修改冲突保护，以及 `/undo` 的终端入口。

执行 `pytest tests/test_change_set.py tests/test_cli.py -q -p no:cacheprovider --tb=short`，结果为 `88 passed`。这证明变更记录不会在失败或无变化时误建，正常文件可恢复，而后续人工修改不会被撤销操作覆盖。
