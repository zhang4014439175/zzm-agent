# P3 阶段验收说明

## 一句话说明

P3 把本地工具执行从“能够调用文件和 Shell 工具”推进为有明确安全边界、可撤销、可取消、可解释的执行闭环。系统会在执行前检查参数、权限和沙箱范围，在执行后记录结果与变更；长结果不会直接塞满模型上下文，所有任务结束原因也会显示并保留。

## 为什么需要它

编码 Agent 会读取文件、修改代码、执行命令和访问外部地址。这些操作一旦缺少统一约束，就可能读到敏感文件、写出工作区、使用模型虚构的参数、覆盖用户后续编辑，或者在取消后继续运行。

单独完成参数校验、沙箱、撤销和上下文压缩还不够。阶段验收需要证明它们能组成同一条用户可理解的执行链路：

- 不合法或越界的操作在产生副作用前被拒绝；
- Agent 修改可以撤销，但不会覆盖用户随后做出的修改；
- 取消和失败不会跳过资源清理；
- 长工具结果保存为 Artifact，模型只接收有限摘要和引用；
- 完成、让出、阻塞、失败和取消都有明确状态，而不是静默回到输入框；
- 终端可以说明正在执行什么、结果是什么以及完整内容在哪里。

## 一个实际使用例子

用户要求 Agent 读取大量测试日志、修改一个文件并运行测试。

1. 文件工具先检查参数结构和路径。读取 `.env` 或工作区外文件会在执行前被拒绝，并返回可理解的沙箱原因。
2. 文件修改经过权限入口。成功后，系统记录修改前后摘要、Patch、工具调用 ID 和会话信息。
3. 如果用户发现修改不合适，可以执行 `/undo`。文件没有被继续修改时会恢复原内容。
4. 如果用户已经手动修改了同一文件，撤销会报告冲突并保留用户版本，不会静默覆盖。
5. 测试命令或日志工具返回大量内容时，完整结果保存为 Artifact。模型上下文只保留摘要、关键片段、校验信息和 Artifact ID。
6. 如果单段工具轮次达到上限，系统保存检查点并自动续段。用户不需要手动输入“继续”。
7. 最终终端显示工具结果和 `completed` 结束原因。如果任务被取消或安全规则阻塞，则显示对应状态和原因。

## 功能的大致流程

1. 模型提出工具调用。
2. 系统校验必填参数、未知字段和基础数据类型。
3. 工具风险等级和权限策略决定是否需要用户批准。
4. 文件路径或网络地址经过沙箱 Profile 检查。
5. 工具执行前检查取消状态和超时边界。
6. 工具执行，并在成功、失败、超时或取消后运行清理回调。
7. 文件修改产生 ChangeSet，记录 Patch 和内容摘要。
8. 工具结果转成 ToolResult。长结果保存为 Artifact，模型只收到受控内容。
9. CLI 根据工具类型展示动态活动描述和结构化结果。
10. 单段达到安全边界时保存检查点并让出；QueryEngine 压缩上下文后自动继续。
11. 任务以 completed、yielded、blocked、failed 或 cancelled 结束，并发布可观察事件。

## 开发前和开发后的区别

开发前：

- 工具参数主要依赖工具函数自行处理，未知参数可能较晚才失败。
- 文件路径、网络地址和敏感文件没有统一 Profile。
- 文件修改缺少持久化变更记录和安全撤销。
- 取消、超时和清理没有贯穿统一工具入口。
- 工具轮次耗尽或空模型回复可能被误认为任务完成。
- 长工具结果容易占满模型上下文。
- 终端只能显示通用工具名，结束原因不够统一。

开发后：

- 无效参数在权限确认和工具执行前被拒绝。
- 文件与网络访问经过确定性沙箱规则。
- Agent 文件修改有 Patch、摘要和冲突保护的撤销能力。
- 取消、超时和清理在工具入口有明确检查点。
- 空回复会有限恢复；单段边界会让出并自动续段。
- 长结果进入 Artifact，压缩后仍保留事实来源。
- 本地工具使用专用 Renderer，所有结束状态都有事件和终端输出。

## 现在已经支持的能力

- 工具参数 Schema 校验和额外字段拒绝。
- 工具风险分级、权限确认及非交互拒绝边界。
- 工作区读写范围、显式拒绝路径和敏感文件保护。
- 网络默认关闭、域名允许/拒绝、localhost 和私网边界。
- 工具超时检查、取消传播和 LIFO 资源清理。
- 文件 ChangeSet、统一 Patch、持久化记录和 `/undo`。
- 用户后续编辑存在时的撤销冲突保护。
- completed、yielded、blocked、failed、cancelled 统一终止状态。
- 空模型回复和 Provider 截断的有限恢复。
- Token Budget、自动压缩、Artifact 化和上下文来源说明。
- Segment 检查点和 QueryEngine 自动续段。
- FileRead、FileEdit、Search、Shell 专用 Renderer 与纯文本降级。

## 当前限制（还做不到什么）

- 当前沙箱主要是应用层路径和网络策略，不是操作系统级进程隔离。
- 同步 Shell 无法在命令执行过程中实时终止所有子进程；真实异步进程树取消属于 P6。
- ChangeSet 主要覆盖受管文件工具，Shell 和 Git 产生的副作用尚未统一进入同一账本。
- 当前撤销以完整文件内容和摘要为边界，不提供代码块级局部撤销。
- Renderer 没有完整交互式 Diff 面板或实时 Shell 输出。
- 基础完成门禁只验证协议和显式状态；基于计划与验收证据的完整 CompletionGate 属于 P5。

## 给开发者看的实现位置

- `zzm_agent/core/tool_registry.py`
  - 参数校验、统一调用、超时检查、取消检查和 cleanup。
- `zzm_agent/core/sandbox.py`
  - `SandboxProfile`：文件和网络访问授权边界。
- `zzm_agent/core/change_set.py`
  - `ChangeSetStore`：记录文件变更、Patch、摘要、撤销和冲突。
- `zzm_agent/core/runtime_state.py`
  - `CancellationToken`、`CancellationController` 和 Turn/Loop 结束状态。
- `zzm_agent/core/context_budget.py`
  - 上下文预算分区与来源说明。
- `zzm_agent/core/segments.py`
  - `SegmentResult`、让出原因和检查点协议。
- `zzm_agent/core/agent_loop.py`
  - 工具权限、执行、恢复、Artifact、Segment 和终止状态主链路。
- `zzm_agent/core/query_engine.py`
  - 自动续段、上下文压缩和基础完成门禁。
- `zzm_agent/core/local_tool_renderers.py`
  - 本地工具专用 Renderer。
- `zzm_agent/cli_support/rendering.py`
  - 工具结果和终止事件的终端展示。

执行链路：

```text
工具调用
→ 参数校验
→ 权限与沙箱
→ 取消 / 超时检查
→ 工具执行与 cleanup
→ ChangeSet / ToolResult / Artifact
→ Segment 检查点或明确结束
→ QueryEngine 自动续段
→ CLI Renderer 展示结果与终止原因
```

## 测试如何证明它有效

新增 `tests/test_p3_acceptance.py`，从用户闭环覆盖四组场景：

1. 无效参数、敏感文件和工作区逃逸在执行前被拒绝，合法工作区路径仍可授权。
2. Agent 文件修改可以撤销；用户随后编辑时，撤销报告冲突并保留用户内容。
3. 预先取消的工具不会执行；正常和失败工具都按逆序完成资源清理。
4. 超长工具结果进入 Artifact，自动续段后完成；后续模型上下文不包含完整大结果，CLI 同时显示工具结果、最终回答和 completed 终止原因。

定向验证：

```text
pytest tests\test_p3_acceptance.py -q
```

结果：

```text
4 passed
```

完整回归：

```text
pytest tests -q
```

结果：

```text
357 passed, 2 skipped
```

这些测试证明 P3 的能力不是彼此孤立的组件：安全拒绝发生在副作用之前，文件变更可以安全恢复，取消不会遗漏清理，长任务可以在受控上下文中继续，并且用户能看到最终状态和原因。
