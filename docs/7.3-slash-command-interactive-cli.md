# 7.3 Slash Command 与交互式 CLI

## 这项功能是做什么的

7.3 把常用运行时操作收敛成 slash command，让用户不用记内部文件路径或 Python 对象，也能在 REPL 里查看状态、恢复会话、检查权限、查看 Artifact、查看计划和发起只读 review。

没有这项能力时，用户只能靠零散命令，例如 `/memory`、`/sessions`、`/config`，很难回答“我现在在哪个会话、用了哪个模型、权限状态是什么、有没有产物、当前计划是什么”。这会让终端版不像一个日常工具，更像只能跑单轮 AgentLoop 的入口。

## 具体例子

用户输入：

```text
/status
```

终端输出当前 session、模型、工作区、stream 状态、工具数量、上下文窗口和 token 用量。

用户输入：

```text
/resume
```

系统会从 `MemoryStore.list_sessions()` 里找到最近的非当前会话并切换。指定 ID 时：

```text
/resume alpha
```

等价于恢复指定历史会话。

用户输入：

```text
/review --cached
```

系统读取 staged diff，构造成只读 review prompt，通过 `QueryEngine.submit_message(stream=False)` 发起审查。提示词明确要求只输出问题，不修改文件、不生成补丁。

## 功能作用

- `/status`：查看当前 session、模型、工作区、stream、工具数、上下文窗口、active turn 和 token 用量；
- `/resume [id]`：恢复指定会话，或无参数恢复最近历史会话；
- `/permissions`：显示权限账本摘要和最近决策；
- `/artifacts [id] [--full]`：列出 Artifact，或预览指定 Artifact，默认只展示前 40 行；
- `/plan`：显示 active task，或只读展示工作区 `task.md` / `implementation_plan.md`；
- `/review [--cached|--staged|commit]`：对 git diff 做只读 AI review；
- `/undo`：在 8.4 ChangeSet 完成前给出明确占位提示；
- `/skills`、`/mcp`：在对应状态未接入前给出清晰占位提示。

## 执行链路

```text
用户输入 slash command
→ run_repl()
→ handle_slash()
→ 对应 _handle_* helper
→ 优先读取 runtime["query_engine"].conversation_state
→ 不存在时读取 runtime["loop"] / MemoryStore / registry
→ 输出普通文本或 Rich 兼容文本
```

`/review` 链路：

```text
/review
→ subprocess.run(["git", "diff"])
→ 截断超长 diff
→ 构造只读 review prompt
→ QueryEngine.submit_message(stream=False)
→ 打印 review 结果
```

## 关键事件或数据结构

- `QueryEngine.conversation_state`：读取 active turn、权限和 Artifact；
- `PermissionState.to_record()`：用于 `/permissions` 摘要；
- `ArtifactStore` / `ArtifactRecord`：用于 `/artifacts` 列表和预览；
- `MemoryStore.list_sessions()` / `switch_session()`：用于 `/resume`；
- `TokenUsage`：用于 `/status` 展示 session token。

## 边界和非目标

- `/undo` 不提前实现 ChangeSet，真正撤销能力放到 8.4；
- `/skills` 和 `/mcp` 不伪造未接入的状态，当前只提供清晰占位；
- `/artifacts <id>` 默认预览，不直接刷完整大内容；
- `/review` 是只读审查入口，不应修改文件或生成补丁；
- 本阶段不做固定底部输入框或 Esc 异步取消。
