# 7.3B 响应语言策略、系统语言检测与全局语言设置

## 这项工作解决什么问题

现在普通问答可以根据用户输入大致跟随语言，但 slash command 没有自然语言问题。例如用户输入 `/review` 时，命令本身是英文标识，内部 prompt 如果写成英文，模型最终总结就容易变成英文；如果在 `/review` 里硬写“请用中文回答”，又会让每个命令都散落一份语言补丁。

7.3B 要解决的是：回答语言应该由统一策略决定，而不是由每个命令临时拼 prompt。用户第一次启动时，如果系统语言是中文，就默认中文；用户一直用中文交流，`/review`、`/plan`、后续 `exec` 也继承中文；用户明确说“用英文回答”，则当前轮按英文回答；用户也可以在全局配置里固定默认语言。

没有这套策略会出现几个失败模式：

- `/review` 没有自然语言正文，最终总结跟随内部英文 prompt，用户看到英文 review；
- `/plan`、`exec`、自动任务等命令各自补语言提示，行为不一致；
- 用户想全局固定中文或英文，只能反复在问题里说；
- 渲染层被迫关心语言，但 renderer 只应该显示事件，不应该决定模型输出语言；
- 后续桌面端无法解释“这一轮为什么用中文/英文”。

## 参考设计

Claude Code 的公开文档展示了两点可借鉴方向：

- 设置有用户、项目、本地、托管等作用域，适合承载个人偏好和团队默认值；
- Output style 会修改 system prompt，说明“回答风格/语言偏好”应进入模型指令层，而不是在渲染层改文本。

Codex 的公开手册也体现了类似结构：

- 用户级 `config.toml`、项目级 `.codex/config.toml` 和 profile 组成配置层；
- `AGENTS.md`、rules、memories 用于长期行为偏好和项目指令；
- 一次性 `--config` 可以覆盖某次运行。

所以 zzm-agent 不应该给 `/review` 单独写中文，而应该实现统一的 ResponseLanguagePolicy。

## 具体例子

### 例子 1：中文系统第一次运行 `/review`

用户没有任何历史会话，只输入：

```text
/review
```

系统检测到 Windows UI / locale 是 `zh-CN`，本轮注入 runtime-only system message：

```text
Respond in Simplified Chinese. Keep code, commands, file paths, API names, and diagnostics in their original language.
```

模型仍然可以用工具执行 `git diff`、`read_file`、`grep_search`，但最终 review 总结使用中文。

### 例子 2：用户临时要求英文

用户输入：

```text
用英文回答：解释这个项目结构
```

本轮语言来源是 `explicit`，输出英文；但不会写入全局配置。下一轮如果用户继续中文交流，仍可回到中文。

### 例子 3：用户全局固定英文

用户设置：

```yaml
ui:
  response_language: en-US
```

之后普通问答、`/review`、`/plan` 和非交互 `exec` 默认都用英文。只有用户本轮明确说“用中文回答”时，当前轮才临时覆盖。

## 语言决策优先级

从高到低：

1. 显式用户要求：`用中文回答`、`answer in English`、`下面用日语`；
2. 当前自然语言输入检测：中文、英文、日文等；
3. 会话最近语言：上一轮自然语言明确是中文，则 slash command 继承中文；
4. 全局配置：`ui.response_language`；
5. 系统 locale：Windows UI 语言、`LANG`、`LC_ALL`、`locale.getlocale()`；
6. 默认 fallback：建议 `zh-CN` 或由配置决定。

## 已新增配置

建议扩展 `config.yaml`：

```yaml
ui:
  response_language: auto
  default_locale_language: zh-CN
```

含义：

- `auto`：自动检测本轮输入、会话语言和系统语言；
- `zh-CN`：全局默认简体中文；
- `en-US`：全局默认英文；
- 后续可扩展 `ja-JP`、`ko-KR` 等。

`/config` 应展示：

```text
response_language: auto
system_response_language: zh-CN
detected_system_language: zh-CN
session_language: zh-CN
last_language_source: session
```

## 已新增模块

```text
zzm_agent/core/language_policy.py
```

核心职责：

- 解析显式语言要求；
- 过滤代码块、路径、命令、文件名后检测自然语言；
- 读取配置默认值；
- 获取系统 locale；
- 返回本轮 `ResponseLanguageDecision`。

建议数据结构：

```python
@dataclass
class ResponseLanguageDecision:
    language: str
    source: str
    confidence: float
    instruction: str
```

`source` 可取：

- `explicit`
- `input_detected`
- `session`
- `config`
- `system_locale`
- `default`

## 执行链路

```text
用户输入或 slash command
→ QueryEngine.submit_message()
→ ResponseLanguagePolicy.resolve()
→ 更新 ConversationState.response_language
→ AgentLoop 构造本轮 runtime-only system message
→ 模型按语言策略输出
→ TerminalRenderer 只负责显示，不决定语言
→ 事件 metadata 可记录 response_language / language_source
```

当前实现中：

- `zzm_agent/core/language_policy.py` 提供 `resolve_response_language()` 和 `ResponseLanguageDecision`；
- `zzm_agent/core/query_engine.py` 在每轮提交前解析语言，并把语言指令作为 runtime-only system message 传给 AgentLoop；
- `zzm_agent/core/agent_loop.py` 支持 `runtime_instructions`，这些指令只进入本轮模型上下文，不写入持久会话历史；
- `zzm_agent/core/runtime_state.py` 在 `ConversationState` 中保存 `response_language` 和 `response_language_source`；
- `zzm_agent/cli_support/commands.py` 的 `/review` 使用 `language_input=command`，避免内部英文审查 prompt 被误判成用户偏好的英文；
- `zzm_agent/cli_support/runtime.py` 创建 `QueryEngine` 时传入完整配置；
- `config.yaml` 新增 `ui.response_language` 和 `ui.default_locale_language`；
- `/config` 展示全局语言配置、会话语言和语言来源。

## 与 `/review` 的关系

`/review` 不应该写：

```text
请用中文回答
```

也不应该写：

```text
Answer in English
```

它只负责把命令转换成审查任务：

```text
Review the current working tree. Use read-only tools to inspect the diff...
```

最终总结语言由 ResponseLanguagePolicy 决定。这样 `/review`、普通问答、`exec`、桌面端都走同一条规则。

## 验收标准

- [x] 中文系统首次启动后输入 `/review`，最终总结为中文；
- [x] 连续中文对话后输入 `/review`，最终总结为中文；
- [x] 英文问题后输入 `/review`，如果会话语言更新为英文，则最终总结为英文；
- [x] 用户输入“用英文回答：...”时，本轮输出英文；
- [x] 用户全局设置 `ui.response_language: zh-CN` 后，slash command 默认中文；
- [x] `/config` 能显示当前语言设置、会话语言和语言来源；
- [x] JSON 事件流中能携带本轮 `response_language` 和 `language_source`；
- [x] renderer 不包含语言判断逻辑。
