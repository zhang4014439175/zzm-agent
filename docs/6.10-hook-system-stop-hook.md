# 6.10 Hook 系统、Stop Hook 与阻塞重试保护

Hook 系统是 zzm-agent 的“运行时拦截点”。它让核心循环在关键位置停一下，把当前状态交给外部规则检查或调整：比如模型调用前检查策略、工具执行前做额外校验、工具失败后记录诊断、最终回答前判断“是不是太早结束了”。

没有 Hook 时，所有行为都必须写死在 `AgentLoop` 里。这样短期简单，但后续权限策略、项目规则、Stop Hook、EventBus、桌面客户端状态展示和 QueryEngine 都会不断往主循环里塞逻辑。6.10 的目标是先建立一套轻量、同步、可测试的 Hook 基础协议，让这些扩展点有固定入口，同时避免 Hook 异常破坏 Agent 主流程。

本阶段先接入同步 `AgentLoop`。异步 Hook、分布式事件、持久化 Hook 记录和 UI 事件流会在 6.11、P6 和后续 QueryEngine 阶段继续扩展。

## 功能作用

本任务主要解决四个问题：

- 让运行时扩展点显式化：Session、Turn、模型、工具、错误和 Stop 都有固定 Hook 类型；
- 让 Hook 可以给出有限决策：继续、阻塞、重试、修改或停止；
- 让 Stop Hook 可以阻止模型过早结束，并要求补一轮回答；
- 通过最大 Stop Hook 次数保护，避免 Hook 一直要求重试导致死循环。

当前支持的 Hook 类型：

```text
SESSION_START / SESSION_END
TURN_START / TURN_END
BEFORE_MODEL / AFTER_MODEL
BEFORE_TOOL / AFTER_TOOL
TOOL_ERROR
STOP
```

当前支持的 Hook 决策：

```text
CONTINUE
BLOCK
RETRY
MODIFY
STOP
```

## 使用场景举例

### 例子 1：Stop Hook 发现最终回答太早，要求继续

用户要求“检查代码并给出修改建议”，模型第一轮直接回答“看起来没问题”，但没有调用任何工具。Stop Hook 可以在最终回答提交前检查当前回复，如果发现回答过短或缺少证据，就返回 `retry`：

```text
STOP Hook -> RETRY("继续检查代码，不要直接结束。")
```

`AgentLoop` 会把这条提示作为 runtime-only system message 加入上下文，再调用模型一轮。这个提示不会写入持久历史，避免污染后续会话。

如果 Stop Hook 连续要求重试超过 `max_stop_hook_attempts`，Loop 会进入 blocked，而不是无限循环。

### 例子 2：工具执行前修改参数

某个项目规则要求所有相对路径都先规范化。`BEFORE_TOOL` Hook 可以读取工具名和参数，在工具真正执行前返回 `modify`：

```text
BEFORE_TOOL(read_file, {"path": "./src/app.py"})
-> MODIFY({"path": "src/app.py"})
```

这样参数修正逻辑不需要写进每个工具，也不需要塞进模型提示词。

### 例子 3：工具失败后统一诊断

工具抛出异常后，`TOOL_ERROR` Hook 可以拿到工具名、参数摘要和结构化错误内容。当前阶段它可以修改回写给模型的错误文本；后续接入 EventBus 后，可以把这类错误统一发布给 UI、日志和回放系统。

### 例子 4：桌面客户端或 QueryEngine 观察 Turn 结束

`TURN_END` 和 `SESSION_END` Hook 能拿到当前状态、最终回复和错误原因。未来 QueryEngine、桌面客户端或测试回放可以基于这些 Hook 更新状态面板、Usage 统计和恢复检查点。

- `zzm_agent.core.agent_loop.AgentLoop`
- `zzm_agent.core.runtime_state.LoopState`

`HookRegistry` 是同步进程内注册器。Hook callback 接收 `HookContext`，返回 `HookResult`、`HookDecision`、字符串决策或 `None`。Hook 抛异常时会被记录为 `hook_error`，并按 `continue` 处理，避免观察者破坏主流程。

## 同步执行链路

`AgentLoop.run()` 当前接入以下 Hook：

- 启动后触发 `SESSION_START` 和 `TURN_START`；
- 模型调用前触发 `BEFORE_MODEL`，允许阻塞或修改模型消息；
- 模型返回后触发 `AFTER_MODEL`，允许阻塞或修改 assistant 文本；
- 工具执行前触发 `BEFORE_TOOL`，允许阻塞或修改工具参数；
- 工具执行后触发 `AFTER_TOOL`，允许修改工具结果文本；
- 工具异常后触发 `TOOL_ERROR`，允许修改回写给模型的错误文本；
- 无工具调用、准备提交最终回答前触发 `STOP`；
- Turn 结束时触发 `TURN_END` 和 `SESSION_END`。

Stop Hook 的重试链路：

```text
model final response
-> STOP Hook
-> RETRY
-> LoopState.activate_stop_hook()
-> append runtime-only system prompt
-> call model again
```

如果 `loop_state.stop_hook_attempts >= max_stop_hook_attempts`，本轮会被标记为 blocked，并返回固定阻塞消息：

```text
Blocked because Stop Hook retry limit was reached.
```

## 边界

- 本阶段 Hook 是同步、进程内机制；
- Hook 不是 EventBus，暂不负责持久事件流；
- Hook callback 异常不会中断 Agent 主流程；
- Stop Hook retry prompt 只进入 runtime messages，不进入 committed history；
- `STOP` 决策当前按继续提交处理，主要保留为后续更细粒度停止协议的枚举值；
- 异步模型流、后台任务、并发工具和子 Agent Hook 会在后续阶段扩展。
