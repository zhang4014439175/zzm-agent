# 8.6 本地工具 Renderer 合集

## 一句话说明

以前终端只能显示“正在运行某个工具”和一段通用结果，用户很难一眼看出它在读哪个文件、搜索什么或执行哪条命令。本次为文件读取、文件修改、搜索和 Shell 命令增加了专用展示方式。终端现在会根据结构化工具参数生成活动描述，并根据结构化结果显示成功、失败、折叠内容和完整结果引用。

## 为什么需要它

工具执行过程中，用户最关心的是三件事：系统现在在做什么、操作对象是什么、最后是否成功。

通用展示只能输出工具名。例如 `Running read_file` 没有说明正在读取哪个文件，也没有显示行范围。Shell、搜索和文件修改同样缺少必要上下文。长结果被折叠或保存为 Artifact 后，通用输出也不容易解释完整内容去了哪里。

专用 Renderer 解决的是展示问题。它不执行工具，不决定权限，也不从一段自然语言中猜测工具状态。它只消费运行时已经确认的工具名、参数、状态、预览和 Artifact 记录。

## 一个实际使用例子

用户要求：“读取 `zzm_agent/core/query_engine.py` 第 1 到 80 行，找到自动续段逻辑。”

1. 模型发起 `read_file`，参数包含文件路径、起始行和结束行。
2. 终端收到工具调用事件后显示：

   ```text
   Running 读取 zzm_agent/core/query_engine.py（行 1-80）
   ```

3. 文件工具完成读取，并生成结构化结果。结果包含状态、终端预览、模型使用的正文和可能存在的 Artifact。
4. 终端选择文件读取 Renderer，显示：

   ```text
   Ran read_file: File: zzm_agent/core/query_engine.py | Lines 1-80 of 420
   ...
   ```

5. 如果结果太长，终端只显示预览，并明确说明折叠了多少行或字符。完整结果若已保存，会同时显示 Artifact ID。
6. 模型继续处理读取内容。Renderer 的展示不会改变模型收到的工具结果。

## 功能的大致流程

1. 模型开始调用工具。流事件携带工具名、调用 ID 和逐步到达的参数。
2. CLI 累加同一调用的参数。只有参数形成完整 JSON 对象后，才用于生成详细活动描述。
3. CLI 根据工具名选择文件读取、文件编辑、搜索、Shell 或默认 Renderer。
4. 工具执行完成后，AgentLoop 发布结构化 ToolResult。事件中同时携带完整参数、风险等级和 ToolResult 记录。
5. Renderer 根据 ToolResult 的状态选择成功或失败展示，不通过结果正文猜测状态。
6. 结果过长时沿用既有折叠策略；存在 Artifact 时显示完整结果引用。
7. 未登记的插件工具或旧事件继续使用默认纯文本 Renderer，不会因为专用集合而无法展示。

## 开发前和开发后的区别

开发前：

- 文件、搜索和 Shell 都只显示通用工具名。
- 活动行无法说明路径、搜索词、行范围、命令或工作目录。
- CLI 的工具结果事件没有接通 AgentLoop 实际执行链路。
- 专用 Renderer 协议已经存在，但主要停留在基础结构和单元测试层。

开发后：

- 文件读取显示路径和可选行范围。
- 文件写入与编辑显示目标路径和变更字符数，不在活动行泄露完整写入正文。
- 搜索显示查询词、范围和文件过滤条件。
- Shell 显示压缩后的命令和可选工作目录，并从稳定结果标记中提取退出码用于展示元数据。
- AgentLoop 在工具完成后发布结构化结果事件，CLI 使用同一 ToolResult 展示。
- 未知工具继续使用纯文本降级。

## 现在已经支持的能力

- `read_file`、`list_directory`、`file_info` 文件读取类展示。
- `file_edit`、`write_file`、`file_append` 文件修改类展示。
- `grep_search`、`find_files` 以及兼容搜索工具名的搜索展示。
- `run_shell` 命令展示。
- 流式参数分段收集和不完整 JSON 安全降级。
- 成功、失败、折叠结果和 Artifact 引用展示。
- Rich 终端与普通文本终端共享相同选择逻辑和事实来源。
- 插件、未来 MCP 工具和未知工具的默认纯文本降级。

## 当前限制（还做不到什么）

- 当前内置 Shell 工具仍是同步执行，因此 Renderer 只能展示开始和最终结果，不能实时滚动 stdout/stderr。真实异步进度属于后续 P6。
- 文件编辑结果目前展示工具返回的简短 Diff 预览，不提供完整交互式 Diff 面板。
- 活动行在参数尚未形成完整 JSON 时只显示工具名。它不会冒险猜测半段参数。
- Renderer 只负责展示，不负责权限、取消、工具调度、Artifact 创建或文件撤销。
- 本阶段没有调整完整 UI 目录结构；该重构属于 P3.5。

## 给开发者看的实现位置

- `zzm_agent/core/local_tool_renderers.py`
  - `LocalToolRenderer`：统一本地工具的开始、进度、成功和失败展示。
  - `FileReadRenderer`：展示读取路径和行范围。
  - `FileEditRenderer`：展示写入或编辑目标及变更规模。
  - `SearchRenderer`：展示搜索词、路径和过滤条件。
  - `ShellRenderer`：展示命令、工作目录和退出码元数据。
  - `build_local_tool_renderer_registry()`：注册内置工具并保留默认降级。
  - `parse_tool_arguments()`：只在流式参数形成完整 JSON 对象后提供给 Renderer。
- `zzm_agent/core/agent_loop.py`
  - 工具完成后把 `ToolResult`、完整参数和风险等级发布为 `tool_result` 流事件。
- `zzm_agent/cli_support/rendering.py`
  - `PlainTextRenderer` 缓存流式参数、选择专用 Renderer，并展示结构化结果。
  - `TerminalRenderer` 复用相同逻辑，只增加 Rich 终端样式。
- `zzm_agent/core/tool_results.py`
  - 提供 `ToolResult`、`ToolProgressEvent`、`ToolRenderContext`、`RenderedToolView` 和 `RendererRegistry` 基础协议。

执行链路：

```text
模型工具调用
→ ModelStreamEvent.tool_call_delta
→ CLI 累加参数并选择本地 Renderer
→ 工具经过权限与统一执行入口运行
→ AgentLoop 创建 ToolResult
→ ModelStreamEvent.tool_result
→ CLI 按结构化状态展示成功、失败、折叠和 Artifact
```

## 测试如何证明它有效

`tests/test_tool_results.py` 覆盖：

- 内置工具是否映射到正确的专用 Renderer。
- 未知工具是否继续走默认纯文本降级。
- 文件、编辑、搜索和 Shell 的动态活动描述。
- 文件写入活动行不会输出完整写入正文。
- Shell 退出码元数据。
- 半段或非对象 JSON 的安全降级。
- 折叠结果和 Artifact 引用。

`tests/test_cli.py` 覆盖：

- 无完整参数时保持旧工具名展示。
- 分段参数不会重复输出活动行。
- 完整参数会生成文件路径和行范围描述。
- CLI 使用 ToolResult 记录展示最终结果。

`tests/test_agent_loop.py` 与 `tests/test_query_engine_streaming.py` 验证工具执行、流事件和 QueryEngine 既有主链路没有回归。

实际验证结果：

- Renderer 与 CLI 定向测试：`95 passed`。
- AgentLoop 与 QueryEngine 定向测试：`56 passed`。
- 完整回归：`353 passed, 2 skipped`。

这些测试证明专用展示已经接入真实流事件，同时没有改变工具权限、模型回填、长结果折叠和未知工具降级行为。
