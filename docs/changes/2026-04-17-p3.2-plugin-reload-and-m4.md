# P3.2 插件热重载与 M4 收口

## 背景

在 `P3.1` 工具确认完成后，`M4` 还缺少一块核心能力：插件热重载。

按 `docs/superpowers/specs/2026-04-10-zzm-agent-v2-requirements.md` 的定义，`P3.2` 需要补齐：

- 提供 `/reload`
- 热重载后展示新增、删除、更新摘要
- 至少保证工具定义刷新

在这次改动之前，插件只会在启动时加载一次。修改插件文件后，必须重启 CLI 才能看到新工具或新描述。

## 本次改动

### 1. ToolRegistry 支持已配置插件目录的重载

更新 [tool_registry.py](/E:/PythonProject/study/zzm-agent/zzm_agent/core/tool_registry.py)，新增：

- `configure_plugin_dirs(...)`
- `load_configured_plugins()`
- `reload_plugins()`

其中 `reload_plugins()` 会：

- 基于当前已配置的 plugin dirs 重新加载工具
- 重建 registry 内部工具表
- 返回三类差异摘要：
  - `added`
  - `removed`
  - `updated`

为保证插件文件里的模块级 `@tool` 装饰器仍能注册到正确的 registry，重载路径里会显式刷新 active registry。

### 2. CLI 增加 `/reload`

更新 [commands.py](/E:/PythonProject/study/zzm-agent/zzm_agent/cli_support/commands.py)，新增：

- `/reload`

当前行为：

- 没有变化时，提示 `No tool changes detected`
- 有变化时，输出：
  - 新增工具数量
  - 删除工具数量
  - 更新工具数量
  - 对应工具名列表

同时 `/help` 已同步加入 `/reload`。

### 3. 启动时插件加载路径统一

更新 [runtime.py](/E:/PythonProject/study/zzm-agent/zzm_agent/cli_support/runtime.py)：

- registry 不再由 runtime 自己循环逐个目录加载
- 改为先 `configure_plugin_dirs(...)`
- 再走 `load_configured_plugins()`

这样启动加载和后续 `/reload` 使用同一条路径，减少分叉逻辑。

## 影响范围

受影响文件：

- `zzm_agent/core/tool_registry.py`
- `zzm_agent/cli_support/commands.py`
- `zzm_agent/cli_support/runtime.py`
- `tests/test_tool_registry.py`
- `tests/test_cli.py`

行为变化：

- `/tools` 会在重载后反映新的工具描述

## 当前边界

这次完成的是“工具定义级别”的热重载，不承诺：

- 插件模块内部全量状态热替换
- 已运行中的调用栈自动切换到新实现
- 更复杂的模块卸载一致性保证

当前保证范围是：

- 工具注册表可刷新
- CLI 可感知新增、删除、更新
- 后续新请求会使用重载后的工具定义
