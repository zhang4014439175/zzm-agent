# 8.10B Slash Command 拆分

## 1. 一句话说明

把 Slash Command 从单文件迁入 commands/ 包，并用 CommandContext 统一注入命令所需依赖。

## 2. 为什么需要它

原 commands.py 同时包含命令识别、会话操作、Git 工作流、运行状态诊断和展示调用，新增命令时很容易扩大依赖面。包化后，路由入口与会话、Git、诊断领域拥有明确模块边界，调用方不再需要逐项拼接依赖参数。

## 3. 一个实际使用例子

用户在 REPL 输入：

    /git status

REPL 仍调用 handle_slash()，路由器把 registry、store、optimizer、console 和 runtime 封装成 CommandContext，Git 领域模块提供对应处理能力，最终结果继续由终端 Renderer 展示。旧的 from zzm_agent.cli_support.commands import handle_slash 无需修改。

## 4. 功能的大致流程

1. REPL 将原始 Slash 输入交给 commands.router.handle_slash()。
2. Router 创建 CommandContext，形成统一依赖边界。
3. 会话、Git 和诊断能力分别由 session.py、git.py、diagnostics.py 暴露。
4. 命令处理函数通过注入的上下文访问当前运行对象。
5. commands/__init__.py 保留稳定公共入口。

## 5. 开发前和开发后的区别

开发前只有一个 commands.py，调用签名长期携带五个独立依赖。开发后使用 commands/ 包，Router、CommandContext 和三个领域模块都可以单独导入、测试与继续演进，同时公共调用方式保持兼容。

## 6. 现在已经支持的能力

- 使用 CommandContext 注入 registry、store、optimizer、console 和 runtime。
- 通过 router.py 提供统一命令入口。
- 通过 session.py 暴露会话恢复能力。
- 通过 git.py 聚合 Git、CI、草稿和撤销命令能力。
- 通过 diagnostics.py 聚合状态、权限、Artifact、Plan 和 Review 能力。
- 保留 cli_support.commands 原导入路径。

## 7. 当前限制（还做不到什么）

命令结果仍沿用当前 console/Renderer 展示协议，尚未升级为面向桌面端或远程协议的完整 CommandResult Schema；这属于后续协议层任务，不在本次目录拆分范围内。

## 8. 给开发者看的实现位置

- zzm_agent/cli_support/commands/context.py：CommandContext。
- zzm_agent/cli_support/commands/router.py：Slash Command 路由与兼容处理。
- zzm_agent/cli_support/commands/session.py：会话命令能力。
- zzm_agent/cli_support/commands/git.py：Git 与 CI 命令能力。
- zzm_agent/cli_support/commands/diagnostics.py：运行诊断命令能力。
- tests/test_cli_directory_splits.py：目录边界与兼容入口测试。

## 9. 测试如何证明它有效

目录拆分测试验证公共入口指向 Router、CommandContext 位于独立模块、三个领域模块都可独立导入。原 CLI 测试继续覆盖全部 Slash Command 行为，证明包化与依赖注入没有改变用户可见结果。
