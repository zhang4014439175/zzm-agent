# 5.1 ProgressMonitor 无进展检测说明

本文档记录 5.1「ProgressMonitor 无进展检测」做了什么，并明确每个功能点对应到哪里的代码。它的目标是让 ReAct 工具循环不仅能靠最大轮数兜底，还能主动识别“已经没有新进展”的失败模式。

## 执行链路总览

5.1 的核心链路是：

```text
AgentLoop.run()
→ 每一轮执行一个或多个 tool_call
→ 将每个工具结果整理成 ToolObservation
→ ProgressMonitor.observe_round(round_observations)
→ 如果检测到无进展，返回 ProgressSignal
→ AgentLoop 根据 ProgressSignal 触发后续处理
```

对应代码：

- `zzm_agent/core/progress_monitor.py`
  - `ToolObservation`：单次工具结果摘要；
  - `ProgressSignal`：无进展信号；
  - `ProgressMonitor`：无进展检测器；
  - `ProgressMonitor.observe_round()`：每轮工具结束后的检测入口；
  - `ProgressMonitor._call_fingerprint()`：工具调用指纹；
  - `ProgressMonitor._observation_fingerprint()`：工具结果指纹。
- `zzm_agent/core/agent_loop.py`
  - `AgentLoop.run()`：创建 `ProgressMonitor`，收集 `ToolObservation`，调用 `observe_round()`；
  - `AgentLoop._no_progress_stop_message()`：生成无进展停止消息；
  - `self.last_progress_signal`：保存最近一次无进展信号。
- `tests/test_progress_monitor.py`
  - `ProgressMonitor` 的单元测试。
- `tests/test_agent_loop.py`
  - AgentLoop 与 ProgressMonitor 的集成测试。

## 1. ToolObservation 工具观察对象

对应代码：

- `zzm_agent/core/progress_monitor.py`
  - `class ToolObservation`
- `zzm_agent/core/agent_loop.py`
  - `AgentLoop.run()` 中构造 `ToolObservation(...)`

这个功能做什么：

`ToolObservation` 是 ProgressMonitor 用来判断进展的最小输入单元。它把一次工具调用的关键信息整理出来：

- `tool_name`：工具名；
- `arguments`：工具参数；
- `content`：工具返回内容；
- `success`：工具是否成功；
- `retryable`：失败是否可重试。

为什么要这样做：

AgentLoop 原始消息里包含模型消息、工具调用、工具结果和运行时上下文，直接拿来做无进展检测太乱。`ToolObservation` 把判断需要的信息抽出来，让检测逻辑和消息结构解耦。

代码上怎么串起来：

```text
工具执行结束
→ result_str / observation_success / observation_retryable
→ ToolObservation(...)
→ round_observations.append(...)
→ ProgressMonitor.observe_round(round_observations)
```

## 2. ProgressSignal 无进展信号

对应代码：

- `zzm_agent/core/progress_monitor.py`
  - `class ProgressSignal`
- `zzm_agent/core/agent_loop.py`
  - `self.last_progress_signal`
  - `AgentLoop._no_progress_stop_message()`

这个功能做什么：

`ProgressSignal` 是 ProgressMonitor 检测到停滞时返回的结构化结果。

字段含义：

- `reason`：无进展原因；
- `round_count`：检测到问题时已经观察了多少轮工具结果；
- `detail`：给模型或用户看的简短说明。

当前可能的 `reason`：

- `repeated_observation`
- `consecutive_non_retryable_failures`
- `repeating_tool_cycle`

为什么要这样做：

如果只返回 `True/False`，AgentLoop 不知道为什么停滞，也无法给模型或用户解释原因。`ProgressSignal` 让后续 Reflection、停止消息、测试断言都能围绕明确原因工作。

## 3. ProgressMonitor 主检测器

对应代码：

- `zzm_agent/core/progress_monitor.py`
  - `class ProgressMonitor`
  - `ProgressMonitor.observe_round()`

这个功能做什么：

`ProgressMonitor` 负责跨工具轮次维护少量状态，并在每一轮工具执行结束后判断是否已经无进展。

内部维护的核心状态：

- 已观察轮次数；
- 最近工具调用指纹；
- 最近 Observation 指纹；
- 连续重复 Observation 次数；
- 连续不可重试失败次数；
- 最近几轮工具调用序列。

为什么要这样做：

ReAct 循环的问题不只是“调用太多次”。更危险的是它可能看起来一直在做事，但每一轮都没有新事实、新文件变化或新结果。ProgressMonitor 就是用来识别这种“忙但没进展”的状态。

## 4. 参数变化但结果重复检测

对应代码：

- `zzm_agent/core/progress_monitor.py`
  - `ProgressMonitor.observe_round()`
  - `ProgressMonitor._observation_fingerprint()`
- `tests/test_progress_monitor.py`
  - `test_detects_repeated_observation_when_arguments_change()`
  - `test_new_observation_resets_repeated_streak()`
- `tests/test_agent_loop.py`
  - `test_agent_loop_stops_when_changed_calls_return_same_observation()`

这个功能做什么：

检测模型不断换参数，但工具返回内容基本一样的情况。

示例：

```text
search(query="alpha") → "no matches"
search(query="beta")  → "no matches"
search(query="gamma") → "no matches"
```

虽然参数变了，但 Observation 没有提供新信息。达到阈值后，ProgressMonitor 返回：

```text
ProgressSignal(reason="repeated_observation", ...)
```

为什么重要：

这种情况很常见：模型不停换关键词搜索，但一直没有结果。如果没有检测，它会烧掉很多轮工具调用。这个检测能提前发现“换参数但没进展”。

## 5. 连续不可重试失败检测

对应代码：

- `zzm_agent/core/progress_monitor.py`
  - `ProgressMonitor.observe_round()`
- `tests/test_progress_monitor.py`
  - `test_detects_consecutive_non_retryable_failures()`
  - `test_retryable_failure_does_not_count_as_non_retryable_stall()`

这个功能做什么：

如果连续多轮工具结果都是不可重试失败，ProgressMonitor 会认为当前执行路线已经停滞。

典型场景：

- 文件不存在；
- 权限不足；
- 参数确定性错误；
- 工具不存在。

检测结果：

```text
ProgressSignal(reason="consecutive_non_retryable_failures", ...)
```

为什么重要：

不可重试错误意味着“重复同样做法没有意义”。如果连续出现这类失败，说明模型应该换路线或向用户报告阻塞，而不是继续撞墙。

## 6. 固定工具循环检测

对应代码：

- `zzm_agent/core/progress_monitor.py`
  - `ProgressMonitor.observe_round()`
  - `ProgressMonitor._call_fingerprint()`
- `tests/test_progress_monitor.py`
  - `test_detects_repeating_two_round_cycle()`

这个功能做什么：

检测多个工具之间形成固定循环。

示例：

```text
read_file("a.py")
search("target")
read_file("a.py")
search("target")
```

如果工具调用序列重复出现，ProgressMonitor 返回：

```text
ProgressSignal(reason="repeating_tool_cycle", ...)
```

为什么重要：

有些 ReAct 死循环不是单个工具重复，而是多个工具之间来回跳。固定工具循环检测就是为了抓这种更隐蔽的循环。

## 7. 工具调用指纹

对应代码：

- `zzm_agent/core/progress_monitor.py`
  - `ProgressMonitor._call_fingerprint()`

这个功能做什么：

把工具名、参数、成功状态和可重试状态归一化后生成指纹。

为什么要这样做：

工具参数可能是 JSON 字符串，也可能顺序不同。指纹化可以减少格式差异造成的误判，让检测逻辑关注“实际调用是否等价”。

## 8. 工具结果指纹

对应代码：

- `zzm_agent/core/progress_monitor.py`
  - `ProgressMonitor._observation_fingerprint()`

这个功能做什么：

把工具返回内容归一化后生成结果指纹。

为什么要这样做：

ProgressMonitor 要判断“这次 Observation 是否真的提供了新信息”。直接比较原始字符串容易受 JSON 字段顺序、空白字符等影响，所以需要先归一化再比较。

## 9. AgentLoop 集成

对应代码：

- `zzm_agent/core/agent_loop.py`
  - `progress_monitor = ProgressMonitor()`
  - `round_observations: list[ToolObservation] = []`
  - `round_observations.append(ToolObservation(...))`
  - `progress_signal = progress_monitor.observe_round(round_observations)`
  - `self.last_progress_signal`

这个功能做什么：

AgentLoop 在每个用户 Turn 内创建一个 ProgressMonitor。每轮工具执行结束后，把本轮工具结果交给 ProgressMonitor 检测。

为什么放在 AgentLoop：

AgentLoop 是单轮 ReAct 循环的执行者，最清楚每一轮工具调用和 Observation。ProgressMonitor 不直接操作消息队列，只负责判断“是否停滞”；AgentLoop 决定后续是 Reflection 还是停止。

## 10. 5.1 专项测试

对应代码：

- `tests/test_progress_monitor.py`
- `tests/test_agent_loop.py`

覆盖场景：

- 参数变化但 Observation 重复；
- 连续不可重试失败；
- 两个工具形成固定循环；
- 新 Observation 会重置重复计数；
- 可重试失败不会被计入不可重试停滞；
- AgentLoop 能把工具结果整理成 Observation 并触发无进展处理。

为什么要这些测试：

ProgressMonitor 是 ReAct 安全底座。它不能靠模型自觉，也不能靠肉眼判断。测试把几类典型死循环固定下来，防止后续改动让 Agent 重新陷入盲目工具调用。
