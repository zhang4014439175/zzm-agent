# 5.2 一次性 Reflection 纠偏说明

本文档记录 5.2「一次性 Reflection 纠偏」做了什么，并明确每个功能点对应到哪里的代码。它的目标是在 ProgressMonitor 检测到无进展后，不是立刻结束，而是给模型一次受控的“换路线”机会。

## 执行链路总览

5.2 的核心链路是：

```text
AgentLoop.run()
→ 工具执行结束
→ ProgressMonitor.observe_round(...)
→ 返回 ProgressSignal
→ AgentLoop._request_reflection(messages, signal)
→ 注入 runtime-only 的 REFLECTION_REQUIRED System 消息
→ 再调用一次模型
→ 如果仍无进展，则停止工具执行
```

重复相同工具调用的熔断也接入同一条链路：

```text
duplicate_tool_call_limit 达到
→ 构造 ProgressSignal(reason="repeated_tool_call")
→ _request_reflection(...)
→ 只允许一次 Reflection
```

对应代码：

- `zzm_agent/core/agent_loop.py`
  - `self.last_reflection_count`
  - `self.last_progress_signal`
  - `AgentLoop._reflection_prompt()`
  - `AgentLoop._request_reflection()`
  - `AgentLoop._no_progress_stop_message()`
  - `AgentLoop.run()` 中 ProgressMonitor 信号处理逻辑；
  - `AgentLoop.run()` 中重复工具调用信号处理逻辑。
- `zzm_agent/core/progress_monitor.py`
  - `ProgressSignal`
  - `ProgressMonitor.observe_round()`
- `tests/test_agent_loop.py`
  - Reflection 相关集成测试。
- `tests/test_agent_replay.py`
  - Replay 下重复工具调用 Reflection 测试。

## 1. Reflection 触发条件

对应代码：

- `zzm_agent/core/agent_loop.py`
  - `progress_signal = progress_monitor.observe_round(round_observations)`
  - `if self._request_reflection(messages, progress_signal): continue`
  - 重复工具调用处构造 `ProgressSignal(reason="repeated_tool_call", ...)`

这个功能做什么：

当 AgentLoop 发现工具执行没有进展时，不是马上停止，而是先尝试注入一次 Reflection 提示，让模型重新评估策略。

触发来源有两类：

1. ProgressMonitor 检测到无进展：
   - 重复 Observation；
   - 连续不可重试失败；
   - 固定工具循环。
2. AgentLoop 原有的重复相同工具调用保护：
   - 连续重复同一个工具和同一组参数达到 `duplicate_tool_call_limit`。

为什么要这样做：

5.1 只能“发现停滞并停止”。5.2 多做一步：在停止前给模型一次换路线机会。这样有些任务可以从错误路线中恢复，而不是直接失败。

## 2. Reflection Prompt 构造

对应代码：

- `zzm_agent/core/agent_loop.py`
  - `AgentLoop._reflection_prompt(signal: ProgressSignal) -> str`

这个功能做什么：

`_reflection_prompt()` 根据 `ProgressSignal` 构造一段运行时 System 消息，开头包含：

```text
[REFLECTION_REQUIRED]
```

提示内容会告诉模型：

- 最近工具执行没有进展；
- 停滞原因是什么；
- 已观察多少轮；
- 不要重复同样或等价工具调用；
- 必须换工具、换参数或换策略；
- 如果缺少用户输入、权限、凭据或外部条件，要停止用工具并报告阻塞；
- 当前用户 Turn 只有一次 Reflection 机会。

为什么要这样做：

这不是让模型输出完整隐藏思维链，而是给模型一个明确的纠偏指令。它的重点是“换路线”而不是“继续解释自己”。

## 3. Reflection 只允许一次

对应代码：

- `zzm_agent/core/agent_loop.py`
  - `self.last_reflection_count`
  - `AgentLoop._request_reflection()`

这个功能做什么：

每个用户 Turn 最多触发一次 Reflection。

代码逻辑：

```text
if self.last_reflection_count >= 1:
    return False

messages.append({"role": "system", "content": self._reflection_prompt(signal)})
self.last_reflection_count += 1
return True
```

为什么要这样做：

Reflection 本身也是一次额外模型调用。如果允许无限 Reflection，Agent 可能从“工具死循环”变成“反思死循环”。所以 5.2 明确限制为一次。

## 4. Reflection 是 runtime-only，不写入持久历史

对应代码：

- `zzm_agent/core/agent_loop.py`
  - `AgentLoop._request_reflection()`
  - 只修改运行时 `messages`
  - 不追加到 `turn_messages`
- `tests/test_agent_loop.py`
  - 检查历史中不包含 `REFLECTION_REQUIRED`

这个功能做什么：

Reflection 提示只存在于当前模型调用上下文，不写入长期会话历史。

为什么要这样做：

Reflection 是一次临时纠偏指令，不是用户消息，也不是最终对话内容。如果持久化到历史里，后续 Turn 可能被旧的纠偏提示污染，导致模型误以为仍处于无进展状态。

## 5. Reflection 不重置 max_tool_iterations

对应代码：

- `zzm_agent/core/agent_loop.py`
  - `tool_iterations` 不因 Reflection 清零；
  - `max_tool_iterations` 判断仍然有效。
- `tests/test_agent_loop.py`
  - `test_reflection_does_not_reset_max_tool_iterations()`

这个功能做什么：

Reflection 不会给当前 Turn 重新开一套工具迭代预算。

为什么要这样做：

`max_tool_iterations` 是硬安全上限。如果 Reflection 重置这个计数，模型可以通过不断进入纠偏流程绕过工具循环保护。5.2 明确避免这种问题。

## 6. Reflection 后仍无进展则停止

对应代码：

- `zzm_agent/core/agent_loop.py`
  - `AgentLoop._request_reflection()`
  - `AgentLoop._no_progress_stop_message(..., after_reflection=True)`
- `tests/test_agent_loop.py`
  - `test_agent_loop_stops_when_no_progress_repeats_after_reflection()`

这个功能做什么：

如果已经触发过 Reflection，后续仍然检测到无进展，AgentLoop 会停止工具执行，并在最终消息里标记 `after reflection`。

为什么要这样做：

这保证 Reflection 是一次纠偏机会，而不是无限续命机制。模型如果换路线仍失败，就应该向用户报告阻塞，而不是继续消耗工具调用。

## 7. 重复相同工具调用接入 Reflection

对应代码：

- `zzm_agent/core/agent_loop.py`
  - 重复工具调用达到 `duplicate_tool_call_limit` 时构造 `ProgressSignal(reason="repeated_tool_call", ...)`
  - 调用 `_request_reflection(...)`
- `tests/test_agent_replay.py`
  - `test_duplicate_call_stop()`
- `tests/test_agent_loop.py`
  - 相关重复调用保护断言

这个功能做什么：

原来的重复工具调用保护是达到阈值后直接停止。5.2 改成：第一次达到阈值时，先给一次 Reflection 机会；如果 Reflection 后仍然重复，才停止。

为什么要这样做：

有时候模型重复工具调用只是因为没理解上一次 Observation。Reflection 可以明确告诉它“不要再重复同一个调用”，给它一次改策略的机会。

## 8. last_progress_signal 和 last_reflection_count 状态

对应代码：

- `zzm_agent/core/agent_loop.py`
  - `self.last_progress_signal`
  - `self.last_reflection_count`
  - `run()` 开始时重置

这个功能做什么：

这两个字段用于记录当前 Turn 的纠偏状态：

- `last_progress_signal`：最近一次无进展原因；
- `last_reflection_count`：当前 Turn 已触发 Reflection 的次数。

为什么要这样做：

这些字段让测试和后续运行时可观测性能够知道：

- 是否发生过无进展；
- 无进展原因是什么；
- 是否已经用掉一次 Reflection 机会。

后续 P1 的 TurnState / LoopState 会把这些临时字段迁移到正式状态对象中。

## 9. 5.2 专项测试

对应代码：

- `tests/test_agent_loop.py`
  - `test_agent_loop_stops_when_changed_calls_return_same_observation()`
  - `test_agent_loop_stops_when_no_progress_repeats_after_reflection()`
  - `test_reflection_does_not_reset_max_tool_iterations()`
- `tests/test_agent_replay.py`
  - `test_duplicate_call_stop()`

覆盖场景：

- ProgressMonitor 发现重复 Observation 后会注入 `REFLECTION_REQUIRED`；
- Reflection Prompt 包含停滞原因；
- Reflection Prompt 不写入持久历史；
- 每个 Turn 最多一次 Reflection；
- Reflection 后仍无进展会停止；
- Reflection 不重置最大工具迭代上限；
- 重复相同工具调用会先进入 Reflection，再按规则停止。

为什么要这些测试：

Reflection 改的是 ReAct 循环控制流。这里如果没有测试，很容易出现两类问题：

- Reflection 没触发，模型继续死循环；
- Reflection 触发太多次，变成新的死循环。
