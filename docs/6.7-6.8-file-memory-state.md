# 6.7-6.8 文件状态缓存与 Memory 加载去重说明

6.7-6.8 做的是把“读过哪些文件、注入过哪些记忆”从临时行为升级成正式运行时状态。

在这之前，`read_file` 每次都会重新读磁盘，Memory 注入只把语义记忆和情景记忆拼成 system message。代码能工作，但运行时并不知道：某个文件是否刚读过、读的是哪些行、文件后来有没有被外部改动、Agent 写入后缓存是否应该刷新；也不知道本轮模型上下文到底注入了哪些 semantic / episodic memory，是否有重复来源，Memory 文件版本是什么。

所以这个合并任务的目标是建立两本轻量账本：

- `FileStateCache`：记录文件内容、Hash、大小、mtime、行数、已读范围、摘要、读取时间、Agent 修改时间和版本；
- `MemoryLoadState`：记录本轮加载的项目 Memory、嵌套 Memory、Skill Reference、semantic / episodic memory ID、Memory 文件版本和重复来源。

一句话概括：6.7-6.8 = 给文件读取和记忆注入建立可观察、可去重、可失效的运行时状态。

## 2. FileStateCache 做了什么

位置：`zzm_agent/core/runtime_state.py`

新增：

- `FileReadRange`
- `FileState`
- `FileStateCache`

每个 `FileState` 记录：

- `normalized_path`：规范化后的文件路径；
- `content_hash`：内容 Hash；
- `size_bytes`：文件大小；
- `mtime_ns`：文件修改时间；
- `encoding`：读取编码；
- `line_count`：总行数；
- `content` / `content_reference`：缓存内容或内容引用；
- `read_ranges`：已读取行号范围；
- `summary`：文件摘要；
- `last_read_at`：最后读取时间；
- `agent_last_modified_at`：Agent 最后修改时间；
- `version`：缓存版本。

关键方法：

- `get_valid(...)`：按大小和 mtime 判断缓存是否仍可用；
- `record_read(...)`：记录一次文件读取；
- `update_after_write(...)`：Agent 写入文件后刷新缓存；
- `invalidate(...)`：外部修改时让旧缓存失效；
- `to_record()` / `from_record()`：支持序列化恢复。

## 3. 文件工具如何接入

位置：`zzm_agent/plugins/file_ops.py`

新增进程级文件状态缓存：

```python
get_file_state_cache()
reset_file_state_cache()
```

接入链路：

```text
read_file(path)
  ↓
规范化并校验工作区路径
  ↓
读取 stat(size, mtime_ns)
  ↓
FileStateCache.get_valid()
  ↓
缓存有效：复用 content，并记录新的 read range
缓存失效或不存在：读取磁盘并 record_read()
  ↓
返回原有带行号文本格式
```

写入链路：

```text
write_file / file_edit / file_append
  ↓
写入磁盘
  ↓
读取最新 stat 和内容
  ↓
FileStateCache.update_after_write()
```

这保证 Agent 自己修改过的文件会立即刷新缓存。用户或外部进程修改文件后，下一次 `read_file` 会通过大小或 mtime 检测到缓存失效并重新读取。

## 4. MemoryLoadState 做了什么

位置：`zzm_agent/core/runtime_state.py`

新增：

- `MemorySourceRecord`
- `MemoryLoadState`

`MemoryLoadState` 记录：

- `loaded_project_memory_paths`
- `loaded_nested_memory_paths`
- `loaded_skill_reference_paths`
- `injected_semantic_memory_ids`
- `injected_episodic_memory_ids`
- `memory_file_versions`
- `sources`
- `duplicate_sources`

关键方法：

- `record_file_source(...)`：记录项目 Memory、嵌套 Memory 或 Skill Reference 文件；
- `record_semantic_memory(...)`：记录 semantic memory，并避免同一来源重复注入；
- `record_episodic_memory(...)`：记录 episodic memory，并避免同一来源重复注入；
- `semantic_memory_id(...)` / `episodic_memory_id(...)`：为记忆条目生成稳定 ID；
- `to_record()` / `from_record()`：支持序列化恢复。

## 5. MemoryStore 如何接入

位置：`zzm_agent/memory/store.py`

`MemoryStore` 新增：

```python
self.memory_load_state = MemoryLoadState()
```

每次调用 `build_memory_messages()` 时，都会创建新的 `MemoryLoadState`，表示“本轮上下文实际加载了什么”。这样不会把某一次 turn 的去重状态错误延续到后续 turn，长期记忆仍然可以在下一轮再次按需检索。

执行链路：

```text
build_turn_messages()
  ↓
build_memory_messages(query=user_input)
  ↓
检索 semantic / episodic memory
  ↓
记录 semantic.json 文件版本
  ↓
记录每个 episodic.json 文件版本
  ↓
record_semantic_memory() / record_episodic_memory()
  ↓
重复来源进入 duplicate_sources，不重复注入 system message
  ↓
memory_load_state.to_record() 写入 compression 元数据
```

`build_turn_messages()` 返回的 compression 元数据现在包含：

```text
memory_load_state
```

后续 QueryEngine、CheckpointStore 或调试 UI 可以直接从这里知道本轮模型上下文有哪些记忆来源。
