# 7.4 非交互 exec、stdin 管道与 JSON 输出

这项工作解决的是“zzm-agent 只能坐在 REPL 里人工操作”的问题。交互式终端适合日常对话，但脚本、CI、批处理、编辑器任务和未来桌面端后台任务都需要一个一次性执行入口：输入任务，运行 Agent，拿到最终结果，并能用机器可读的方式记录过程。如果没有这个入口，用户只能把问题复制进 REPL，CI 不能自动调用，其他程序也很难消费工具调用、语言来源、最终回答和失败原因。

典型场景是代码库在 CI 失败后自动调用：

```powershell
git diff --name-only | zzm-agent exec --stdin --json "审查这些变更文件"
```

这个命令会把用户 prompt 和 stdin 文件列表合并成同一轮任务，使用和 REPL 相同的 `QueryEngine`、`AgentLoop`、配置、记忆、权限和语言策略执行；如果指定 `--json`，每个流式事件会按 JSONL 输出，最后再输出一条 `result` 记录。脚本可以逐行读取事件，展示进度或保存日志；CI 可以根据退出码判断成功失败。

## 解决的问题

- 让 Agent 能被脚本、CI、批处理和编辑器命令调用，而不是只能人工进入 REPL。
- 让 stdin 管道成为正式输入来源，方便接收 `git diff`、日志、文件列表或测试输出。
- 让 JSONL 事件流成为机器可读协议，后续桌面端、App Server、CI 日志和回放系统可以复用。
- 让最终回答可以写入文件，例如生成 review 报告、commit message 草稿或 release notes。
- 让非交互模式不会卡在权限确认界面；需要人工批准的工具会被拒绝并进入正常工具结果链路。
- 提供 shell completion 脚本输出入口，方便终端补全 `exec`、`--stdin`、`--json`、`--output` 等命令。

## 使用例子

普通一次性执行：

```powershell
zzm-agent exec "总结这个项目结构"
```

stdin 管道输入：

```powershell
git diff --name-only | zzm-agent exec --stdin "审查这些文件是否有风险"
```

JSONL 事件流：

```powershell
zzm-agent exec --json "查看当前工作区并总结问题"
```

输出最终结果到文件：

```powershell
zzm-agent exec --output review.md "根据当前 diff 写一份中文审查报告"
```

生成 shell completion：

```powershell
zzm-agent completion powershell
zzm-agent completion bash
zzm-agent completion zsh
```

## 执行链路

```text
parse_args()
→ main()
→ load_config()
→ build_runtime()
→ run_exec()
→ _build_exec_prompt()
→ QueryEngine.submit_message()
→ resolve_response_language()
→ AgentLoop.run()
→ ModelStreamEvent
→ JSONL stdout / plain stdout / output file
```

REPL 和 `exec` 共享 `build_runtime()`，因此模型配置、插件加载、记忆、指令文件、权限状态、语言策略、事件和状态快照都走同一套运行时。区别是 `exec` 不启动 prompt session，不显示欢迎页，不进入循环，也不会打开交互式权限选择器。

## 关键行为

### stdin 合并

`zzm-agent exec --stdin "review"` 会读取标准输入。如果 prompt 和 stdin 同时存在，最终提交给 `QueryEngine` 的内容是：

```text
review

Input from stdin:
<stdin 内容>
```

如果没有 prompt，但有 `--stdin` 内容，则直接使用 stdin 作为任务内容。没有 prompt 也没有 stdin 时，命令返回退出码 `2`。

### JSONL 事件流

`--json` 模式下，每一行都是独立 JSON。事件记录来自 `ModelStreamEvent.to_record()`，并额外带上 `type: "event"`：

```json
{"type":"event","kind":"status","text":"turn.started","metadata":{"response_language":"zh-CN","language_source":"config"}}
```

执行完成后输出一条结果记录：

```json
{"type":"result","reply":"最终回答","response_language":"zh-CN","language_source":"config"}
```

如果执行失败，会输出：

```json
{"type":"error","message":"错误说明"}
```

### 输出文件

`--output path` 只写最终 assistant message，不写 reasoning、工具事件或 JSONL 过程事件。目录不存在时会自动创建。没有 `--json` 且指定 `--output` 时，stdout 保持安静，方便脚本只关心退出码。

### 非交互权限

`exec` 使用 `build_noninteractive_confirmation_callback()`。当工具风险需要确认时，它不会弹出菜单，也不会等待 stdin，而是返回拒绝。这样 CI 不会挂死；拒绝结果会按原有 AgentLoop 权限链路回写给模型，让模型解释无法继续的原因或改用只读路径。

## 对应代码

- `zzm_agent/cli_support/runtime.py`
  - `parse_args()`：新增 `exec` 和 `completion` 子命令。
  - `run_exec()`：非交互执行入口。
  - `_build_exec_prompt()`：合并 prompt 与 stdin。
  - `_json_event_line()` / `_json_result_line()`：JSONL 输出协议。
  - `_write_exec_output_file()`：最终结果写文件。
  - `build_noninteractive_confirmation_callback()`：非交互权限拒绝。
  - `render_completion_script()`：输出 shell completion 脚本。
- `zzm_agent/core/query_engine.py`
  - 继续作为非交互和交互 REPL 的统一执行入口。
- `zzm_agent/core/model_stream.py`
  - `ModelStreamEvent.to_record()` 提供 JSONL 事件基础结构。
