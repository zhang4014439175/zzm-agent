# 9.1 最小 MCP stdio 客户端

## 一句话说明

现在可以连接一个本地启动的 MCP 服务，读取它提供的工具并在 zzm-agent 中调用它们。外部工具不会成为安全旁路，仍会经过现有的参数检查、权限策略、超时和结果记录。

## 为什么需要它

以前工具只能由项目内的 Python 插件直接注册。想接入本地文件索引、数据库或其他工具服务时，没有统一的启动、握手、发现和关闭方式。

## 一个实际使用例子

用户配置一个提供 `greet` 工具的本地服务。系统启动该服务，先确认双方都能使用的通信版本，再取得工具清单。服务的 `greet` 会以 `mcp.<服务名>.greet` 出现在工具列表中。

当模型请求它并传入 `{"name": "Ada"}`，系统先检查 `name` 是否存在且为文字，再把请求发给服务。服务返回“hello Ada”，结果和本地工具一样被回填。若用户或模型漏传 `name`，请求在发往服务前就会被拒绝。

## 功能的大致流程

1. 启动一个由用户配置的本地 stdio 服务。
2. 发送初始化请求并记录服务基本信息。
3. 读取服务公布的工具清单。
4. 为每个工具建立带服务名前缀的受管入口，避免覆盖本地工具。
5. 调用时先走正常的参数校验和权限链路，再转发给服务。
6. 唯一读取线程把响应交给对应请求；期间出现的通知不会打断调用，服务日志会被持续排空。
7. 关闭时尽力通知服务并终止子进程；CLI 正常退出或异常结束都会执行清理。
8. 协议、启动或超时错误会给出明确错误；发现中途失败会撤销已经注册的代理工具。

## 开发前和开发后的区别

开发前，项目没有可实际通信的 MCP 客户端。开发后，一个 stdio 服务能够完成初始化、工具发现、调用和关闭，并以普通工具形式被使用。

## 现在已经支持的能力

- 单个 stdio MCP Server。
- initialize、initialized、tools/list、tools/call 与 shutdown。
- 服务工具的 JSON Schema 参数校验、名称隔离和本地超时。
- 启动失败、无效 JSON、超时、远端错误的隔离报错。
- 合法通知和请求响应交错、有限 stderr 日志尾部以及失败后的原子回滚。
- CLI 退出时统一关闭全部已连接服务，不遗留受管子进程。
- 在 `config.yaml` 的 `mcp.servers` 中配置服务；`/mcp` 可显示已连接服务、发现的工具和连接错误。

配置示例：

```yaml
mcp:
  servers:
    - name: local-tools
      command: ["python", "path/to/server.py"]
      timeout_seconds: 15
```

## 当前限制

暂不支持 HTTP、SSE、WebSocket、多服务重连、OAuth、动态工具更新或后台连接治理。这些属于后续可选扩展或后续 P4 任务。

## 给开发者看的实现位置

- `zzm_agent/core/mcp_client.py`：stdio JSON-RPC 生命周期、工具发现和调用代理。
- `zzm_agent/core/tool_registry.py`：`register_external_tool()` 将远端 Schema 纳入现有注册、校验与调用边界。
- `zzm_agent/cli_support/bootstrap.py`：读取 `mcp.servers`、隔离单个服务的启动错误。
- `tests/test_mcp_client.py`：以本地临时服务验证完整协议链路、通知交错、stderr 排空、超时、回滚、配置错误隔离和 CLI 退出清理。

## 测试如何证明它有效

执行 `pytest tests/test_mcp_client.py -q`。测试会启动真实子进程服务，验证握手、发现、参数拒绝、权限风险标记、通知交错、日志排空、超时、工具结果和关闭清理。

本次实际验证结果：

- MCP、ToolRegistry 与 CLI 定向回归：`110 passed`。
- 全量回归：`395 passed, 2 skipped in 77.12s`。
